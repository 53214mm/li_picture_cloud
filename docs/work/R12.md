# R12 · 提案 / 聊天实体化

## 需求确认 / 设计

- 基线：Nexus 主线 `5177cf4`；R11 代码与独立 review 已通过，真实浏览器验收仍受环境阻塞，不能标 DONE。
- 本轮是独立的 R12 前端增量：点击现有伙伴入口，在原生互动抽屉原位聊天；主页与抽屉共用一份账号内会话；已观察到的 PENDING 提案在身体/Shell 给克制提示，用户点击才预览。
- 非目标：新增聊天端点、模型/额度/认证规则、自动发言、改变自主契约、轮询生成提案、后台代理执行、重画资产、无关重构。
- 依赖：R08 原生 dialog/图片交接、R06 页面观察租约和已取得的 proposal 事实、现有历史 GET 与 SSE POST。不依赖 R11 视觉验收通过。
- 风险：双入口重复请求/发送、关闭后晚到响应、账户私密记录交叉、history 覆盖正在发送的消息、把断流当作持久化成功、提案读取惰性生成、焦点落到禁用输入框。
- 验收：入口点击前没有新增 IO；拖图检查不拉取聊天；双入口共享一份历史/草稿/请求；最后一个消费者退出或账号变化后晚到响应无效；失败不变成伙伴台词、不自动重发；待确认发送先显式读回历史；提案只展示已取得 PENDING、无额外 proposal/contract 调用；键盘/触摸与取消有回归用例。
- 验收目标档位：**V3**（需求跟踪表明确指定 R12 V3）。本轮完成 V2 层级的前端自动证据；真实 Home/history/SSE 与后端故事线联调仍是 V3 未完成项，不能因为 HTTP 契约未改就降低目标档位。浏览器、真实 API 联调均未宣称通过。

## 实现 / 迭代

稳定代码提交：`0648c559c8195fbebd865c58f8d57e97e53dacd1`。独立 review 已通过，无未解决阻断性代码发现。后续 STATE-only 提交记录该 SHA 为验证对象，避免自引用状态提交 hash。

- `companionChatSession.js`：纯会话控制器、不可变快照、消费者租约、history single-flight、单发送、明确刷新、账号 reset。
- `stores/companionChat.js`：每个 Pinia/账号一份会话，首次真实消费者才发请求；没有持久化、轮询或后台任务。
- `CompanionChatPanel.vue`：主页与 compact 共用组件/会话；不同 input/title ID、实例内 scroller，避免查询全局第一个聊天记录。读取历史时可先写草稿，提交仍锁定；发送/未决时转向完整页聚焦稳定标题。
- `CompanionQuickChat.vue`：仅用户打开抽屉且非图片检查时挂载，读取 Home 确认已有伙伴与对话模式；不会抢占主页观察租约。离开/账号变化时丢弃晚到结果并 abort 客户端读。
- SSE 只增加可选 AbortSignal 和 reader 清理；URL、method、请求正文、cookie 契约不变。保留既有 EOF 结束接收兼容语义，但**不声称 EOF 证明服务端持久化成功**；服务端已有显式 done 未改。
- 最后一个消费者退出时停止客户端接收，清除历史缓存、保留同账号未发送草稿；已发但未确定的请求显示待核对提示。关闭并不意味着服务端操作取消。重新打开不会自动重发；需显式「刷新对话」后再由用户决定发送。
- 提案预览只取当前 Home 租约已观察的 pending ID/content；保留服务器决定能否主动，点击提示不调用 proposal/contract 接口。回应按钮到既有原提案区域，接受/忽略/敲打保持原实现。
- Review 预检修复平板侧栏选择器误替换；修复历史未加载时「打开完整对话」的焦点问题，并新增延迟历史用例。
