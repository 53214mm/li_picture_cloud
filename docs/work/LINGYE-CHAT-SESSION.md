# 绫页对话分段与聊天经历（2026-10-10）

## 为什么改

上午聊过一个话题，下午随口说一句别的，她还是接着上午的话题聊。原因是每轮都把最近 20 条消息原样发给模型，不管隔了多久，也不带时间；在模型眼里，上午最后一句就是下午这句的上一句。

## 现在怎么工作

1. **分段**：重新登录，或距上一句超过 2 小时（`app.companion.chat-session-gap`），就开始新的一段。聊天列表和模型上下文都只含当前这一段；旧消息仍在库里。
2. **整理经历**：每轮都检查有没有还没整理的旧对话。有的话用本轮同一条模型路由（自己的 Key 优先，否则平台）整理成一两句经历，写进 `companion_chat_episode`。
   - 最多整理最近两段；更早积压的记录直接跳过，不逐段补。
   - 对方说的话加起来不到 8 个字（比如只说了"你好"），不调模型，记为没有内容。
   - 模型输出"无"表示这段没有值得记住的事，同样占位推进进度。
   - 整理失败不影响聊天，下一轮再试；不扣平台试用额度，但记一次模型用量。
3. **想起经历**：经历和图片记忆一样走 pgvector 语义召回（单独一张表 `companion_episode_vector`），相似度不够的不进提示词；向量库不可用时退回字面匹配。对方问"上次聊了什么""昨天说的那个"时，再补上最近两段。
4. **时间**：提示词新增"时间"一节，写明现在几点、距上次说话多久。新的一段会明确告诉她：之前的话题已经过去，对方没提起就不要主动扯回去。想起的经历标上"今天上午""昨天晚上""4 天前"这样的相对时间。
5. **清空**：试演台的"清空对话记录"会一并删除经历，向量在下次召回时对账删除。

## 新增的表

- `companion_chat_episode`：经历，`companionId + lastMessageId` 唯一，防止并发的两轮重复整理。
- `companion_chat_boundary`：每个用户最近一次登录的时间（登录时通过 `UserLoggedInEvent` 写入，失败不影响登录）。
- pgvector 里的 `companion_episode_vector`：首次使用时自动创建。

## 未验证

- 整理经历的提示词还没用真实模型跑过，总结的质量和"无"的判断需要试聊确认。
- 新的一段的第一句会先整理上一段，这一句的回复会慢几秒。
