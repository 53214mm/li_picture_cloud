# 绫页普通聊天额度与平台入口修复（2026-10-10）

## 复现与范围

唯一目标 `nexus/mainline-r11`，基线 `156d88ee8d403d8590bafb14367dfcc9f3df563f`。工作区起始干净；origin 与实际 fetch 回读均为目标仓库/分支。用户反馈外接 DeepSeek 仍有每日条数上限，以及新账号无法使用平台模型；截图是普通聊天面板，不是主动试演。

已确认三处问题：

1. `CompanionChatService` 在选路之后无条件预占每日聊天次数，导致自费 BYOK 和不外发的 DEMO 也被平台日桶拦截。旧代码位置的真实回归：已有桶耗尽时 BYOK、DEMO 两项均报“今日伙伴对话次数已用完”；平台受限用例正常通过。
2. 已发布配置没有 `chat-policy`，落到配置对象安全默认 `DEMO_ONLY`；新用户因此看见演示模式和不可切换的真实模型。这是已证实的入口配置原因，不把用户平台供应商账户或密钥是否正常作无证据推断。
3. 前端把 HTTP 403 的明确准入拒绝也当成可能已提交的流中断，要求刷新历史。新增前端回归修复前 12 项失败，覆盖直接 transport 与共享 session。

## 修复契约

- 普通聊天日桶只预占平台 `MODEL`；BYOK 和 DEMO 不读取/增加这个桶，也不动平台钱包。既有桶不重置、不迁移；它已满时平台仍拒绝，BYOK/DEMO 可继续。没有改主动 presence/手动试演/视觉额度。
- 平台日上限仍为 50，试用钱包仍是每主体懒初始化 100，并保留成功结算、失败/取消释放预占、已发起平台尝试的日次数不退还。无无限平台消费许可，无 BYOK 失败静默回退。
- 发布 YAML 明确 `COMPANION_CHAT_POLICY` 默认 `MODEL`，并可用 `COMPANION_CHAT_DAILY_LIMIT` 调整平台日额度；Compose 透传与 `.env.example` 同步。用户已明确选择 DEMO 的偏好不强行改写。显式 `DEMO_ONLY` 继续禁止平台外发；整个伙伴功能的生产默认关闭保持。
- 模型模式只在平台策略允许且唯一可初始化 `ChatModel` bean 存在时提供平台入口。缺失、歧义或初始化失败均安全关闭；这是配置可用性，不是有效密钥、供应商健康或真实模型调用验收。BYOK 模式不为此初始化平台模型。
- 最终路由之后再次检查平台准入，防止读取用户模式后 BYOK 规则被并发移除而绕过显式 `DEMO_ONLY`。坏 BYOK 仍明确失败，不换平台。
- 20 次/分钟 endpoint 限流、500 字输入、12,000 码点上下文、历史窗口、取消/超时和既有有界请求机制保留。未新增未经证实的服务端跨实例并发保证。
- HTTP 400/401/403/404/429 的明确准入拒绝仅在尚未收到任何正文时移除未发送的乐观消息、恢复草稿、显示原错误，不要求刷新历史。408/5xx、网络错误、SSE error、部分文字和缺少 done 的 EOF 仍按不确定处理；无自动重试，账号隔离、取消和迟到回调边界保留。
- 前端平台文案说明“将使用平台模型”，不可用文案说明平台未启用或暂不可用，并把连接自己的模型作为可选途径，不声称已验证真实可用。
