# R11 · 情绪 / 关系 / 性格可视化

## 需求确认 / 设计

- 基线：main `d49fd06645995e6f2c0a67a6f230ae6704afb2e4`（R10 完成）；仅 Nexus 长期分支。
- 目标：让伙伴的既有情绪/关系/性格先以克制的状态描述、静态图形和身体节奏呈现，精确数值下沉。
- 范围：R06 mapper 的增量展示投影、R07 单计时器 Idle 变体、Home 现有身体与三个状态面板；沿用原素材。
- 非目标：新的领域状态、后端/API 变化、新资产/依赖、主动通知、音频、聊天/提案重构、全站重构。
- 依赖：现有 Home DTO / 租约、新鲜度、R06 affect/rapport 优先级、R07 资源/可见性生命周期。
- 风险：把 energy=0 误解释为疲劳、错误数据假装中性、喂养旧快照回流、性格与短期情绪混淆、动作在暂停/后台继续、披露控件破坏旧测试。
- 验收：只有完整合法且 fresh 的观察驱动表现；缺失/非法/stale 不显示假数值；五种情绪、关系和性格可读，原数值可键盘/触摸展开；现有活动/提案优先且无新请求；暂停/减少动态保持静态；相关回归无退化。
- 档位：V2，纯前端消费现有 API，不要求无关后端改造。浏览器运行失败须区分环境阻塞与产品断言失败。
