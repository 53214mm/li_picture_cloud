# Codex 项目接管学习手册

本目录记录从 `main` 基线开始，对 DeepSeek 功能分支进行分阶段学习、审查、整改和验证的过程。

目标不是保存一份“AI 已经看过”的结论，而是让项目维护者能够：

- 说清楚主要业务流程；
- 从 HTTP 入口追踪到领域规则和持久化实现；
- 判断事务、并发、权限和数据一致性风险；
- 理解并决定哪些设计应该保留、简化或重构；
- 为每个准备合入 `main` 的阶段留下可复核证据。

## 固定基线

- 稳定基线：`main@11a6182`
- DeepSeek 扫描目标：`origin/deepseek/companion-mood-relationship-memory@7e8885f`
- 正式审查时，每个阶段必须重新记录实际 base、target 和工作区状态。

## 学习方式

每个单元依次回答：

1. 业务目的是什么；
2. 谁是入口，调用链如何流动；
3. 核心代码负责什么；
4. 涉及哪些 Java、Spring 和数据库知识；
5. 为什么采用当前设计；
6. 如果删除或改错会发生什么；
7. 哪些结论已经验证，哪些仍待验证。

知识深度使用三个等级：

- **必须掌握**：需要能够独立解释并逐步自己实现；
- **需要看懂**：看到类似代码时能识别用途、边界和风险；
- **暂时知道即可**：当前只需知道它为什么存在，不展开框架内部细节。
