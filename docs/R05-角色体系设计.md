# R05 — 角色体系设计（待选择）

日期：2026-09-23。这里只定义概念边界与资产组织意图；没有新建表、接口、状态协议或生产渲染器。

最新人工指示：A 绫页暂留，B/C 冻结；A 的 Web 成熟体采用设定页左侧正常比例全身立绘，Q 版只保留作未来 Codex 式桌宠参考。用户已要求提交推送当前探索稿，技术路线尚未决定。

## 1. 身份所有权

| 概念 | 拥有什么 | 不拥有什么 |
| --- | --- | --- |
| CompanionSpecies | 官方身份、种族、稳定人格底色、世界文化背景、三阶段视觉基因、资产母版与可用表现 | 用户私有记忆、关系数值、已发生的个人经历 |
| CompanionInstance | 唯一 id、owner、未来 species 关联、用户取名、未来孵化时间、现有生命经验/等级/阶段、Traits、Mood、Relationship、Memory 关联 | 一套独立复制的 Runtime 或新的角色模板 |
| Appearance / Art revision | 服装、皮肤、资产版本、不同设备的表示 | 新的生命、重置成长、另起记忆 |
| Representation | Shell Presence、Scene Sprite、Conversation Portrait | 决定实际生命阶段或业务权限 |

未来概念唯一约束是 `(userId, speciesId)`。Species 的边界是「官方可养成的一种角色模板」，不是现实生物分类法。同物种文化背景下若再发布不同官方角色模板，是否仍算同一 Species 必须在发布规范中明确，不能用新增 skinId 绕过唯一性。

现有领域 `ownerId` 与持久层 `userId` 指向用户，不因此再引入第二套所有者。`Companion.id` 应成为未来 Instance 身份的延续，`lifeExperience` 是现有 EXP 名称。Mood / Relationship / Memories 可以继续通过 companionId 关联，不必塞进同一张大表。

用户命名、孵化时间、Events、Keepsakes 和自主生活 Story 是未来需要表达的能力；目前不能假装都已存在。已有 StoryDraft 是创作能力，与伙伴生平应分开。

## 2. 身份连续性的不可变条件

- 蛋被分配给用户后就属于同一个 Instance；孵化、成熟、换装、艺术升级、浏览器与 Desktop 切换都不能换 id。
- 关系与记忆绑定 Instance，而非 PNG 文件名、皮肤、设备、运行时对象或前端 session。
- 官方形象修订有 artVersion；不能因为升级模型重新计算过去 Feed，也不能回滚用户的成长。
- 同种第二次获得不产生重复实例；具体如何退回/提示/转为其它获取机会属于未来获取流程，本轮不编造补偿货币。
- 「忘记」「纠正」「图片撤权」的规则不因身体有了表情而改变。

## 3. 现有数据的冲突必须显式处理

当前 `UNIQUE(userId)` 比目标 `(userId, speciesId)` 更严格。当前读写按 `findByOwnerId` 选择单个伙伴，聊天、喂养、契约、记忆上下文都依赖这个前提。**多角色上线不是仅增加图片或修改唯一索引。**

未来如实施多实例，需要独立设计与测试：旧数据如何获得 speciesId、原 companionId 保留、所有关联归属、当前活跃伙伴选择、接口中的实例授权、幂等键作用域、当前单实例 API 的兼容行为及回滚。R05 不做这些迁移，也不承诺某个 R06～R12 会顺手完成。

生命周期还有另一处冲突：`LIGHT → SEEDLING → COMPANION` 是现有等级推导；目标是 `Egg → Juvenile → Adult`，其中 Egg 涉及真实孵化状态。

| 当前事实 | 设计中的候选处理 | 禁止的快捷处理 |
| --- | --- | --- |
| 已存在 LIGHT，可能已有聊天和成长 | 保留状态并设计老伙伴身份认领；确认后可探索未成熟视觉过渡 | 把旧实例倒退成不能交流的未孵化蛋 |
| SEEDLING | 与 Juvenile 有语义近似，可作为以后兼容映射候选 | 当作迁移已确定或更改历史等级 |
| COMPANION | 与 Adult 有语义近似，可保留成年视觉候选 | 将 Q 版强制解释为降级/幼年 |
| 尚未唤醒 | 继续视为不存在 Instance 的当前事实 | 从空数据假造已有蛋和孵化倒计时 |

原型提供阶段切换仅为了看设计，绝不读取真实 `lifeStage`。将来 Egg 是独立孵化状态还是统一生命周期的一段，需要结合业务再确认；R05 不制定新的状态字段/协议，也不直接把 LIGHT 改名 EGG。

## 4. 两个正交维度

| 生命阶段 | Shell Presence | Home Scene Sprite | Conversation Portrait |
| --- | --- | --- | --- |
| Egg | 具有种族轮廓的静态小卵 | 场景中的卵与固定落点 | 近景卵形，不假装已有成年面孔或成熟台词能力 |
| Juvenile | 简化的未成熟体 | 较简单的服装、尚未展开的生物特征 | 相同未成熟特征的半身，不按现实幼儿年龄叙事 |
| Adult | A 使用正常比例全身缩略，保留文字入口；不自动回退 Q 版 | A 使用设定页左侧正常比例全身，预留脚底与动作边界 | 同一正常比例角色的半身裁切，表情更清楚 |

Q 版是艺术比例，和现实年龄、生命周期无一一对应。Juvenile 的区别必须来自形态与结构发育，而不是把 Adult 缩小 60%。

原 A Q 版作为独立桌宠参考留档，不删除原图、不重新命名为幼体，也不作为本轮 Web 主体。保留此参考不意味着已确定桌宠宿主或要制作 Codex 宠物包。

同一角色的 Sprite 和 Portrait 共享：主色块、发型分区、眼色、种族轮廓、一个服装锚点与一个主题纹样。优先保持这些视觉不变量；小尺寸可以删纹理、纽扣与缝线，不能删掉全部非人特征。

## 5. 三个产品表现位置

### Shell

沿现有 Presence 的位置增补安静的小身体。概念建议：224px 桌面侧栏中使用约 64px 高 Sprite，保留「伙伴空间」文字和至少 44px 可触达区域；88px 平板侧栏改成约 48px 简化 Sprite + 短标签；手机保留现有静态伙伴入口，不挤进全身人物。

实际现有标记容器只有 40×44，不能声称直接塞 64px 就无布局影响。第二阶段需要在槽位内部评估高度，保持侧栏整体可滚动与导航可用；这轮只在隔离原型展示候选。

Hover / Focus 先使用一致的边界、底色、焦点环；角色的微小反应是以后 R07/R08 的扩展。原型最多只有可暂停的整体呼吸示意，不算合格帧动画，不映射 Mood。没有红点、随机气泡或右下角漂浮客服球。

功能关闭：移除 Presence 并回收布局位置，不加载角色资源。未唤醒：未来产品决策前沿用「进入伙伴空间」中性入口。状态读取失败：显示静态入口与真实错误，不编造睡觉。业务弹层开启：保持 Shell inert，停止动效与指针响应，不越过现有 drawer/modal 层级。

### Home

优先全身与稳定地面接触。为最大轮廓留出包围盒：A 翼宽，B 背壳与低尾，C 横向尾巴。所有动作的 feet anchor 一致；转身/行走若需要新视角，应进入正式资产计划，不能靠把正面左右翻转解决不对称服装。

### Conversation

在对话内容一侧放半身构图；窄屏收成小头像/静态缩略图，把文本放前。Portrait 表情由真实交互结果驱动是后续工作，今天只示意中性与好奇的构图。不能通过可爱表情暗示模型成功、记忆已确认或提案已执行。

## 6. 资产扩展方式（设计意图，不是 R06 协议）

建议将可替换美术资源组织成 `species → artVersion → lifeStage → representation`，每包附许可出处、设计母版、图片大小、裁切范围、feet anchor、安全边距、静态 fallback 和制作工具版本。动作文件今后由 R07 确定；不要今天冻结一组前后端状态 enum。

例如 `paperwing / art-v1 / adult / shell` 与 `paperwing / art-v1 / adult / portrait` 是同一身份的两个视图。用户 id 不拼到公共 CDN 美术路径里。私人图片和未来纪念品内容使用原有授权路径，不能放进公开角色包。

| 增长规模 | 表现层应如何扩展 | 仍然要投入什么 |
| --- | --- | --- |
| 第 2 个角色 | 同样的画框、锚点与资源选择机制；添加一套资产和视觉元信息 | 新的原画、三阶段、表情与动作 QA；多实例业务尚须单独实现 |
| 第 5 个角色 | 只预加载活跃实例的 Shell；进入 Home/Chat 再载对应包；切换释放旧资源 | 可用动作清单与缺失动作的静态 fallback，不能全员常驻 GPU |
| 第 10 个角色 | 用资源清单校验、版本控制和制作模板维持一致；缩略图与全尺寸分开 | 系列角色的识别度测试、组合测试、资产许可证与包体预算维护 |

一个可替换渲染适配层能降低将来 Sprite 换 Spine 的业务耦合，但不代表动画资产可以自动转换。美术生产源文件的保留比提前实现庞大的 Runtime 抽象更重要。

## 7. 选择后第一版生产资产最小清单

本表是未来交付规格建议，**这些文件本轮没有生产**。

| 交付物 | 最少内容 | 验收重点 |
| --- | --- | --- |
| 身份母版 | Adult 正面、侧/背结构说明、色板、种族特征、不可改变项 | 同人设可反复画出，缺角/左右不镜像漂移 |
| 成长母版 | Egg / Juvenile / Adult 同页与比例尺 | 去名字后能连成一条成长线，Juvenile 结构不同 |
| 三阶段全身静态 | 各 1 张 alpha PNG/WebP，feet anchor 和占位一致 | 透明无脏边；无人物裁断；前端不靠手调每张位置 |
| Shell 简化图 | 已选阶段的 48/64/80px 检视，必要时专门重画大色块 | 64px 保留至少两项种族特征；40px 不硬塞立绘 |
| 对话静态 | 已选可交流阶段中性半身 1 张；阶段扩展再配套 | Sprite / Portrait 的同一人识别；蛋不借用成年头像 |
| 最小 Idle | 首个获准接入的阶段 4–6 帧眨眼/轻呼吸，或所选骨骼模型的同等一动作 | 不漂脚、不循环闪烁；可停止在静态帧；不是完整 R07 |
| 单一 Home 布景 | 空房间/地面锚点、照片架留位 | 不包含真实业务或其它 NPC |
| 资源说明 | 来源权利、工具/导出版本、尺寸、锚点、命名、静态后备、预算记录 | 能持续交给后续制作，能审计而非只剩一张 AI 图 |

如果正式 R05 选择同时展示三个阶段，三个阶段都需要对应静态 fallback；不要求把全部情绪状态与三个阶段相乘制作。资产动作的增加应由 R07/R08 的真实交互驱动。
