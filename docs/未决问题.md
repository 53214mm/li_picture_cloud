按“阶段指南/验收清单优先、用户授权优先”与季度边界登记下列范围未完成项，供后续季度独立设计与实现：

1. **统一能力内核 discover / invoke / observe 未实现（Q3 未完成项）**：ModelCapabilityRegistry 目前只是静态能力画像查询；模型调用、MCP 工具与本地能力仍是独立路径，没有统一能力目录、统一守门与异步观察。设计依据见 `docs/superpowers/specs/2026-08-14-model-mcp-control-center-design.md` §2.6 与 roadmap Q3（统一能力内核）。影响：表情草稿所需的“视觉理解执行器”、多图融合所需的“多参考图图像适配器”都将随该内核统一设计与实现。
2. **多图融合玩法未开放（登记于 2026-09 阶段 4 整改）**：现有图像适配器只支持文生图（images/generations），无 reference image / image edit 输入；为不产生误导性血缘，`FusionImageService.generate` 一律明确失败（不调用模型、不预占/结算、任务转安全失败终态），前端明示“真实多图融合能力尚未开放”。待支持多图参考输入的适配器完成供应商能力验证后开放。
3. **表情草稿玩法暂未开放（登记于 2026-09 阶段 4 整改）**：文字表情候选必须来自“授权图片的视觉理解安全摘要”（人物/动作/表情/物体元素），不能用图片数量与分类模拟；`EmojiDraftService.generate` 一律明确失败（不调用语言/视觉模型、不预占/结算、任务转安全失败终态），前端明示需要视觉理解能力。待视觉理解执行器（随统一能力内核落地）后开放。
