暂无阻塞当前实现的未决问题。

## 明确延期项（不阻塞当前轮，登记待排期）

按“阶段指南/验收清单优先、用户授权优先”与季度边界登记下列范围未完成项，供后续季度独立设计与实现：

1. **统一能力内核 discover / invoke / observe 未实现（Q3 未完成项）**：ModelCapabilityRegistry 目前只是静态能力画像查询；模型调用、MCP 工具与本地能力仍是独立路径，没有统一能力目录、统一守门与异步观察。设计依据见 `docs/superpowers/specs/2026-08-14-model-mcp-control-center-design.md` §2.6 与 roadmap Q3（统一能力内核）。影响：表情草稿所需的“视觉理解执行器”、多图融合所需的“多参考图图像适配器”都将随该内核统一设计与实现。
2. **多图融合玩法未开放（登记于 2026-09 阶段 4 整改）**：现有图像适配器只支持文生图（images/generations），无 reference image / image edit 输入；为不产生误导性血缘，`FusionImageService.generate` 一律明确失败（不调用模型、不预占/结算、任务转安全失败终态），前端明示“真实多图融合能力尚未开放”。待支持多图参考输入的适配器完成供应商能力验证后开放。
3. **表情草稿玩法暂未开放（登记于 2026-09 阶段 4 整改）**：文字表情候选必须来自“授权图片的视觉理解安全摘要”（人物/动作/表情/物体元素），不能用图片数量与分类模拟；`EmojiDraftService.generate` 一律明确失败（不调用语言/视觉模型、不预占/结算、任务转安全失败终态），前端明示需要视觉理解能力。待视觉理解执行器（随统一能力内核落地）后开放。
4. **token 用量只覆盖平台非流式语言调用与图片生成（明确未完成，不得当作已闭环）**：控制中心的“用量（输入 / 输出 / 图片）”目前只在两条路径上是真实值——平台路径非流式 `ChatModel.call` 响应元数据（故事大纲/草稿，取 prompt/completion tokens），以及 BYOK 图片生成（成功即记 1 张）。以下路径**尚未采集用量**，表中显示 `— / — / —`：
   - BYOK 流式语言调用（`LanguageModelInvoker.stream` → `Flux<String>`，流式分片不携带 usage 元数据，`StoryDraftService` 与配方工坊因此只能记 `ModelUsageSnapshot.none()`）；
   - 伙伴对话流式回复（`CompanionChatService.recordUsageSuccess/Failure` 走的是无用量重载，同为 `Flux<String>` 路径，拿不到 token）；
   - 连接测试（`ModelConnectivityService` 使用无用量重载：该调用只验证连通性，不产出内容）；
   - 视觉理解调用（`RoutedVisualObservationProvider` 使用无用量重载，`DashScopeVisionClient` 目前不解析响应里的 usage 字段）。
   影响：控制中心不能声称“token 用量已全覆盖”，按量计费/成本核算（见 `docs/metrics/companion-funnel-metrics.md` 的成本指标）目前只有部分数据。建议轮次：与统一能力内核（第 1 条）一并设计 usage 统一出口后再补齐；补齐前不得在验收清单上勾选“用量闭环”。
5. **`rawUsage` 列暂不写入（登记于 2026-09 阶段 4 整改）**：`model_usage_record.rawUsage` 列已建（迁移 changeSet 20260814-39），但应用层不再把供应商原始计量文本（`nativeUsage.toString()`）落库——它是任意供应商文本，无法保证不含隐私或超预期内容。需要时只按白名单计量键（如 totalTokens/cachedTokens）单独设计写入与展示，不整体透传。影响：列当前恒为 NULL，控制中心不展示该字段。
6. **配方 WHEN 的自动执行与全类型投递仍未开放（登记于 2026-09 阶段 5 整改）**：WHEN 已真实接入机会源（阶段 3 守门通过后投递机会 → 生成 `PENDING_CONFIRM` 待确认执行记录 → 用户确认才调用 THEN），但仍有两个明确边界：
   - **不自动执行**：没有任何调度器或后台任务会自动创建创作任务；`THEN` 永远需要用户确认；
   - **一次评估只投递当次观察到的机会**：机会源按 @Order 优先级短路（每周回顾 → 纪念日 → 相似图片），且伙伴侧已有 PENDING 提案时不再评估，因此其他 WHEN 类型的配方要等下一次评估才可能被触发。
   影响：不能声称"配方已支持全自动/全类型触发"。补齐需要把机会评估从"按需+优先级短路"改成"全类型观察 + 独立投递"，属于统一能力内核（第 1 条）之后的排期项。
