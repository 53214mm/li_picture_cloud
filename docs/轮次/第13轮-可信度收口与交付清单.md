# 第 13 轮：可信度收口与交付清单

## 什么叫“后端可信度收口”

功能能跑只是第一层。可信还要求：同样的代码在另一台机器能构建；错误配置不会悄悄进入生产；架构规则不会被下一次修改破坏；依赖漏洞能尽早被发现；失败时能知道失败在哪一步。

因此最后一轮不再增加业务功能，而是把前面各轮的质量要求变成机器会执行的规则。

## 本轮完成的检查

### 1. 领域层依赖护栏

`DomainDependencyTest` 会扫描领域源码，禁止它依赖 Spring、MyBatis、Servlet 和旧数据库实体。以后有人误把 `@Service` 或 Mapper 放入领域层，CI 会直接失败。

这比写一句“请遵守 DDD”可靠，因为文档可能被忘记，测试不会。

### 2. 覆盖率报告

Maven 引入 JaCoCo。执行 `mvn verify` 后，HTML 报告生成在 `target/site/jacoco/index.html`，CI 会上传 `backend-jacoco-report` 构建产物。

当前先生成和保存报告，没有设置全项目百分比闸门。原因是旧 AI、分析和上传模块测试基础薄弱，仓促设置总百分比只会鼓励无意义测试。后续应按上下文设置增量门槛。

### 3. 前端生产依赖审计

CI 在测试前执行 `npm audit --omit=dev --audit-level=high`。只要生产依赖出现高危漏洞就失败。命令显式指定官方 npm registry，避免开发机镜像不支持审计接口造成误报。

本轮已升级锁文件中的 axios、form-data、postcss 等安全修复版本；生产依赖审计结果为 0 个漏洞。Vite 开发服务器仍有中等级别公告，但它是开发依赖且不进入生产包，升级到新主版本应另开兼容性任务。

### 4. 依赖日志冲突清理

DashScope SDK 传递引入 `slf4j-simple`，同时 Spring Boot 使用 Logback，导致运行时提示多个日志实现。本轮排除了传递依赖，统一由 Logback 输出，避免日志丢失和配置不确定。

### 5. 生产配置收紧

新增 `application-prod.yaml`：

- 生产 Cookie 强制 Secure、HttpOnly、SameSite=Lax；
- 关闭 MyBatis SQL 控制台输出；
- 关闭 OpenAPI 和 Swagger 页面；
- WebSocket 允许来源必须由 `COLLABORATION_ALLOWED_ORIGINS` 明确配置，不能退回 localhost。

启动生产环境时使用：

```powershell
$env:SPRING_PROFILES_ACTIVE = "prod"
$env:COLLABORATION_ALLOWED_ORIGINS = "https://你的前端域名"
java -jar target/li-picture-cloud-0.0.1-SNAPSHOT.jar
```

## 最终验证命令

后端：

```powershell
$env:JAVA_HOME = "你的 JDK 21 目录"
.\mvnw.cmd -B "-Dspring.profiles.active=test" verify
```

前端：

```powershell
cd li-picture-cloud-frontend
npm ci
npm run lint
npm test
npm run build
npm run check:bundle
npm audit --omit=dev --audit-level=high --registry=https://registry.npmjs.org
```

## 从第 4 轮到第 13 轮得到了什么

- 权限规则、权限注解、全局异常和权限查询接口具备回归测试；
- 静态与动态分片均可通过 profile 开关；
- 团队编辑者可通过 WebSocket 协同旋转和缩放，客户端支持重连、版本冲突恢复与最终保存；
- 性能由基准数据驱动，当前明确不引入 Disruptor；
- 身份访问、空间成员、图片读取、协同状态机开始按 DDD 边界迁移；
- CI 同时验证后端、前端、覆盖率产物、包体预算和生产依赖安全。

## 仍需部署环境配合的事项

跨后端实例的协同状态共享仍记录在 `docs/未决问题.md`。它需要 Redis 状态模型和真实双实例环境，不能用单机测试伪装成已解决。除此之外，本轮未留下阻塞当前单实例交付的问题。
