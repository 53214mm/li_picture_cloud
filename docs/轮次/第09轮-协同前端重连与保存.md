# 第 09 轮：协同前端、重连与保存

## 1. 页面怎样知道能不能协同

图片详情加载后，前端把图片编号交给 `/spaceUser/permissions`。后端根据登录用户、图片所属空间和成员角色返回权限。只有包含 `collaboration:edit` 时，按钮才显示“协同编辑”。

这不是唯一安全措施。用户即使手工构造 WebSocket 地址，后端握手和每条消息仍会再次校验。

## 2. WebSocket 客户端负责什么

`CollaborationClient` 把浏览器原生 WebSocket 包成一个小模块：

- 根据页面协议自动选择 `ws` 或 `wss`；
- 连接时带 `pictureId`；
- 把 JSON 事件通知给 Vue 组件；
- 发送 UUID、操作和当前版本；
- 意外断线自动重连；
- 用户关闭弹窗时主动断开且不重连。

开发服务器的 `/api` 代理增加了 `ws: true`，所以本地开发也能代理 WebSocket。

## 3. 重连为什么使用指数退避

如果服务器短暂故障，所有浏览器每 100 毫秒重连会形成更大压力。本轮间隔依次为 1、2、4、8 秒，之后最多 10 秒。连接成功后次数归零。

## 4. Canvas 怎样同步别人的操作

前端不在收到“右旋”后自行再加 90 度，而是使用事件里的完整状态：`rotation`、`scale`、`version`。这种绝对状态同步能容忍丢消息：即使漏掉中间一次操作，下一条完整状态仍能恢复一致。

每次从原图按绝对角度重绘，避免反复压缩带来的画质累积损失。异步图片转换还带序号，较旧转换晚到时会被忽略，防止快速点击导致画面倒退。

## 5. 保存发生了什么

用户点击“保存并替换”时：

1. 编辑器按最终旋转和缩放输出 PNG Blob；
2. 前端沿用 `/picture/upload` 的更新模式，提交文件和原图片 ID；
3. 后端用统一权限服务检查 `picture:edit`；
4. 合法团队 editor 也能保存，不再只允许原上传者；
5. 保存成功后关闭弹窗并重新读取图片详情。

保存是显式动作，实时操作本身只改变协同会话状态，不会每次点击都上传新文件。

## 6. 当前测试范围

Node 测试使用假的 WebSocket，贯穿客户端的连接、服务端状态、版本命令、意外断线重连和主动关闭，可稳定运行在 CI。它不替代真实双浏览器测试；真实环境仍应人工或用 Playwright 验证两名团队成员同时打开同一图片的场景。
