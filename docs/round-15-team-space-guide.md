# 第 15 轮使用指南：从创建团队到协同编辑

这份文档写给第一次运行本项目的同学。你不需要先读完后端源码，按顺序操作即可完成团队空间的创建、成员管理和协同编辑验证。

## 1. 先理解两种空间

### 私有空间

私有空间用于管理自己的图片。其他普通用户不能以团队成员身份加入。一个用户最多创建一个私有空间。

### 团队空间

团队空间由创建者负责管理。创建者可以添加成员并分配角色；具有编辑权限的成员可以上传、修改、删除图片，并共同编辑同一张图片。一个用户最多创建一个团队空间，但可以加入多个由其他用户创建的团队。

创建团队空间时，系统会自动把创建者加入成员表并设为管理员。创建者不能被移除，也不能被降级，这保证团队始终有一个稳定的负责人。

## 2. 三种团队角色

| 角色 | 可以做什么 | 不可以做什么 |
| --- | --- | --- |
| 查看者 | 查看空间和图片 | 上传、修改、删除、协同编辑、管理成员 |
| 编辑者 | 查看、上传、修改、删除图片，加入协同编辑 | 管理团队成员 |
| 管理员 | 拥有编辑者全部能力，并能添加、修改和移除成员 | 删除或降级团队创建者 |

页面上的按钮只是为了让操作更直观。真正的权限仍由后端检查，因此即使有人绕过页面直接请求接口，也不能越权操作。

## 3. 运行前准备

需要准备：

- JDK 21；
- MySQL 8；
- Redis；
- Node.js 22；
- 两个测试账号，下面称为账号 A 和账号 B。

后端连接信息建议通过 IDEA 运行配置的环境变量填写，不要把密码直接写进 Git：

```text
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=li_picture_cloud
MYSQL_USERNAME=root
MYSQL_PASSWORD=你的 MySQL 密码
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=你的 Redis 密码
```

如果 Redis 确实没有密码，就删除 IDEA 中的 `REDIS_PASSWORD` 环境变量，不要填写空格或示例值。项目配置 `${REDIS_PASSWORD:}` 会在变量不存在时使用空字符串。

## 4. 创建团队空间

1. 登录账号 A。
2. 打开“我的空间”。页面标题下会显示账号 A 的用户 ID。
3. 点击“创建空间”。
4. 选择“团队空间”。
5. 选择普通版，填写团队名称，例如“图片设计组”。
6. 点击“创建空间”。
7. 创建成功后，页面自动进入新团队空间。

如果看到“每个用户每类空间仅能有一个”，说明账号 A 已经创建过团队空间。返回“我的空间”，在“我创建的团队空间”中进入已有团队即可。

## 5. 查找账号 B 的用户 ID

最简单的方式：

1. 在另一个浏览器或无痕窗口登录账号 B。
2. 打开“我的空间”。
3. 复制标题下方的“我的用户 ID”。

用户 ID 是长整数，复制时不要手动改写，也不要用 JavaScript `Number` 转换。项目页面和 API 会把雪花 ID 当字符串传递，避免精度丢失。

平台管理员还可以在用户管理页面查看用户列表中的 ID。

## 6. 添加成员并修改角色

回到账号 A 的团队空间：

1. 点击右上角“成员管理”。
2. 在“用户 ID”中粘贴账号 B 的 ID。
3. 角色选择“编辑者”。
4. 点击“添加成员”。
5. 成功后，账号 B 出现在成员列表中。

成员列表支持修改角色和移除成员。创建者一行会显示“创建者”，其角色选择和移除按钮不可用。当前管理员也不能在这个面板中移除自己；后续若需要主动退出团队，应走单独的退出团队流程。

## 7. 账号 B 进入团队

1. 切换到账号 B 的浏览器。
2. 刷新“我的空间”。
3. 在“我加入的团队空间”中找到“图片设计组”。
4. 卡片上应显示“团队空间”和“编辑者”。
5. 点击卡片进入团队空间。

编辑者应当看到上传图片、批量管理和图片编辑操作，但看不到“成员管理”。如果角色刚被修改，刷新页面以重新获取服务端权限。

## 8. 双账号验证图片协同编辑

先由账号 A 或账号 B 上传一张图片到团队空间。然后：

1. 账号 A 打开该图片详情。
2. 账号 B 也打开同一张图片详情。
3. 两边点击“协同编辑”。
4. 等待状态显示“协同已连接”。
5. 账号 A 执行左旋、右旋、放大、缩小。
6. 观察账号 B：图片效果应实时变化，并显示操作提示。
7. 再由账号 B 操作，观察账号 A 是否同步。

协同消息由 WebSocket 传输，状态与跨实例事件通过 Redis 协调。页面只在团队空间且当前用户拥有 `collaboration:edit` 权限时显示“协同编辑”。私有空间仍使用普通单人编辑。

## 9. 验证查看者权限

1. 账号 A 打开成员管理。
2. 把账号 B 从“编辑者”改为“查看者”。
3. 账号 B 刷新团队空间。
4. 账号 B 仍能浏览图片，但上传、批量管理、编辑、删除和协同编辑入口都应消失。
5. 如果账号 B 直接调用修改接口，后端也应返回无权限错误。

这个步骤可以证明权限不是只靠前端隐藏按钮。

## 10. 常见报错

### “该用户已在团队中”

同一个用户在一个团队只能有一条成员记录。直接在列表中修改已有成员角色，不要重复添加。

数据库脚本 `sql/space.sql` 还定义了 `(spaceId, userId)` 唯一索引，用于阻止两个并发请求同时插入重复数据。

### “用户不存在”

检查粘贴的用户 ID 是否完整，并确认对方账号已经注册。不要填写用户名；本轮接口按数字用户 ID 添加。

### “不能移除团队创建者”或“团队创建者必须保留管理员角色”

这是正常保护规则。创建者永远是团队管理员，不能在成员管理中删除或降级。

### MySQL：`Access denied for user 'root'@'localhost'`

这表示应用已经连接到 MySQL，但用户名或密码不正确。检查 IDEA 运行配置中的 `MYSQL_USERNAME` 和 `MYSQL_PASSWORD`。修改环境变量后必须停止并重新启动应用。

### Redis：`NOAUTH Authentication required`

Redis 服务配置了密码，但应用没有发送正确密码。检查 Redis 配置中的 `requirepass`，并让 `REDIS_PASSWORD` 与它一致。

如果 Redis 没有密码，却出现认证问题，优先检查 IDEA 是否还保存着旧的 `REDIS_PASSWORD`。环境变量会覆盖 `application.yaml` 中的默认空值。

### WebSocket 一直显示重连

依次检查：

1. 后端是否正常启动在 `8124` 端口；
2. Vite 代理是否把 `/api` 的 WebSocket 请求转发到后端；
3. Redis 是否可连接；
4. 当前图片是否属于团队空间；
5. 当前成员是否是编辑者或管理员；
6. 浏览器开发者工具的 Network → WS 中是否有握手失败信息。

不要通过删除权限校验来解决连接问题。握手返回 401/403 时，应修复登录态或成员角色。

### npm 审计使用国内镜像时返回 404

部分镜像不实现 npm 安全审计接口。可以只为本次命令指定官方端点：

```powershell
npm audit --audit-level=high --registry=https://registry.npmjs.org
```

这不会永久修改本机 npm registry。

## 11. 开发者验证命令

在项目根目录验证后端：

```powershell
$env:JAVA_HOME='G:\JDK\Java\jdk-21'
.\mvnw.cmd "-Dspring.profiles.active=test" test
.\mvnw.cmd "-DskipTests" package
```

在 `li-picture-cloud-frontend` 目录验证前端：

```powershell
npm ci
npm test
npm run lint
npm run build
npm run check:bundle
npm audit --audit-level=high --registry=https://registry.npmjs.org
```

如果 Windows 提示某个 `esbuild.exe` 无法删除，通常是前端开发服务器仍在运行。先保存工作并停止对应的 `npm run dev`，再执行 `npm ci`；不要直接结束与本项目无关的 Node 进程。

前端当前使用 Vite 7.3.6 和 `@vitejs/plugin-vue` 6.0.8。升级的原因是旧版 Vite 间接依赖的 esbuild 存在开发服务器安全公告。不要执行 `npm audit fix --force`，因为强制升级可能跨越主要版本且绕过项目验证。

## 12. 本轮没有做什么

第 15 轮只补齐团队空间业务闭环，页面沿用现有视觉基础。整站导航、布局宽度、字体层级、颜色、卡片、表格、表单、空状态和移动端体验将在第 17 轮统一改版。这样可以先确保业务正确，再集中处理视觉一致性，避免同一页面反复返工。
