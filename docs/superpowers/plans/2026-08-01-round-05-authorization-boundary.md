# 第 5 轮实施计划：权限边界、异常协议与接口测试

## 目标

把第 4 轮的纯权限规则接到 HTTP 接口上，使“谁、对哪个资源、执行什么操作”能够在进入业务方法前被统一判断；同时让异常的 HTTP 状态与业务码语义一致。

## 实施顺序

1. 先用测试固定异常到 HTTP 状态的映射，以及权限注解的放行/拒绝行为。
2. 新增 `@SpacePermission`，用 SpEL 从控制器参数中显式提取 `spaceId`、`pictureId` 或 `spaceUserId`。
3. 新增权限访问服务，负责加载空间、图片和成员关系，再调用第 4 轮的纯策略。
4. 给空间成员管理接口应用权限注解，避免每个控制器手写相同判断。
5. 提供“获取当前用户对资源的权限集合”接口，供前端决定按钮是否展示。
6. 全局异常处理返回正确的 400/401/403/404/500 HTTP 状态，同时保留原业务响应体。
7. 运行聚焦测试、完整 Maven 打包、差异检查，随后提交、推送并观察 CI。

## 验收条件

- 未登录返回 HTTP 401；无权限返回 HTTP 403；参数错误返回 400；资源不存在返回 404。
- 成员管理接口要求 `spaceUser:manage`。
- 权限查询接口只返回服务端计算结果，不接受客户端自报角色。
- 注解不读取原始 JSON 流，避免请求体被重复消费。
- 所有返回权限集合不可修改。
