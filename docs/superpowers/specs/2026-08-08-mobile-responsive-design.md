# LiPictureCloud 全站移动端适配设计

## 背景与目标

LiPictureCloud 当前包含首页、登录注册、公共图库、图片详情与上传、个人/团队空间、空间分析、图片审核和用户管理等 13 个路由页面。现有前端以桌面布局为主，仅少数页面包含局部媒体查询，移动端存在导航拥挤、筛选与分页溢出、表格难以操作、弹层超出视口、编辑器工具栏依赖横向空间、图表密度过高等问题。

本次改造覆盖全站，目标是在不改变后端接口、权限模型和核心业务流程的前提下，使所有页面在手机和平板上可阅读、可操作、无页面级横向溢出，并尽量保持现有瑞士平面设计语言与桌面效果。

## 验收视口

- 360–767px：完整手机布局，重点验证 360、390 和 430px 宽度。
- 768–1023px：平板过渡布局，同时覆盖横屏。
- 1024px 及以上：保留现有桌面布局和信息密度。
- 页面主体不得产生横向滚动；图片编辑画布和代码/数据等明确的内部滚动区域除外。
- 触控目标不小于 44×44px，相邻主要触控目标保持至少 8px 间距。
- 支持浏览器缩放、键盘操作与 `prefers-reduced-motion`，不得禁用 viewport 缩放。

## 总体方案

采用“响应式基础设施 + 共享组件改造 + 复杂页面定向适配”的方案，不引入新的 UI 框架或运行时依赖。

1. 在全局样式中建立统一的容器边距、触控尺寸、焦点样式、安全区、移动弹层、按钮组、分页和减少动态效果规则。
2. 以现有桌面样式为 1024px 以上基线，通过 1024px、768px 和 480px 附近的媒体查询逐级降低信息密度。
3. 导航、图片列表等共享组件承担可复用行为；后台表格、编辑器、分析图表在各自边界内完成专门适配。
4. API 请求、Pinia 用户状态、路由地址和权限判断保持不变，移动端仅改变呈现与局部交互状态。

## 导航设计

移动端采用已确认的方案 A：分组抽屉导航。

- 顶部栏保留品牌标识和 44px 菜单按钮。
- 抽屉从右侧进入，导航按“浏览”“工作空间”“管理”“账户”分组。
- 普通用户与管理员仍由当前 Pinia 用户状态决定可见入口；桌面菜单和移动抽屉使用同一导航数据，避免权限入口不一致。
- 抽屉支持遮罩点击、关闭按钮、Esc、路由切换自动关闭；打开时锁定页面背景滚动。
- 当前路由具有清晰的活动状态；退出登录与普通导航在视觉和空间上分离。
- 桌面宽度下不渲染抽屉交互，保持现有横向导航。

## 全局响应式基础

- `.container` 在桌面保持 2rem 边距，平板降至 1.5rem，手机降至 1rem。
- 全局按钮与表单控件在手机端保证至少 44px 高度；纯图标按钮扩展点击区域并提供可访问名称。
- 为 `:focus-visible` 提供统一、高对比度焦点环，保留键盘导航反馈。
- 标题使用 `clamp()` 或断点字号，长用户名、标签、文件名和统计值允许安全换行或省略。
- 固定/粘性元素考虑 `env(safe-area-inset-*)`；页面根节点使用动态视口高度语义，避免移动浏览器地址栏造成裁切。
- 弹层在桌面保持居中卡片，手机端采用接近底部面板的全宽布局，限制高度并让内容区独立纵向滚动；操作按钮保持可见。
- 在减少动态效果模式下关闭页面淡入、抽屉位移、卡片缩放和其他非必要动画。

## 页面与组件行为

### 首页、登录与注册

- Hero 标题、说明和搜索框在手机上缩小间距，搜索输入与按钮在极窄视口下纵向排列。
- 热门标签保持换行且每个标签具有足够触控高度。
- 特色卡片单列；马赛克保留两列但取消依赖 hover 的反馈，必要时在 480px 以下调整跨列项。
- 登录、注册卡片使用手机边距，不出现固定宽度；表单按钮在手机上铺满可用宽度。

### 公共图库与图片列表

- 搜索框、搜索按钮、筛选项在手机上变为单列或两列自适应布局；筛选值不得因 `max-width` 保持窄宽。
- 图库在 360px 为单列，在较宽手机和平板按空间自适应为两列或更多列，卡片内容始终可见。
- 卡片快捷操作不能依赖 hover；触摸设备上常显或通过明确按钮进入。
- 复选框和快捷操作扩大点击区域。
- 分页在手机上分行：上一页/下一页作为第一行，页码信息和跳页作为次级内容；极窄视口可隐藏非关键的跳页控件。

### 图片详情、上传与分享

- 图片详情由双栏切换为单栏，图片优先，元数据、审核、业务操作随后呈现。
- 元数据网格在窄屏改为单列或紧凑两列；动作按钮组成可换行的全宽按钮组，删除操作与普通操作分离。
- 上传页、空间内上传面板的拖放区、URL 输入、命名和提交按钮在手机上纵向排列。
- 分享、编辑信息和图片编辑弹层使用移动弹层规则；二维码按视口缩放。
- 全屏图片查看和编辑尊重安全区，关闭按钮保持 44px 点击面积。

### 空间体系与 AI 面板

- 我的空间网格在手机上单列；AI 卡片取消固定 520px 的刚性高度，改用受视口约束的最小/最大高度。
- 空间详情页标题、容量信息、成员按钮和上传入口分组换行；批量操作工具栏在手机上纵向排列。
- 空间成员侧栏在手机上占据全宽，成员行允许角色选择与操作换行。
- AI 快捷指令支持横向内部滚动或多行换行，输入区保持发送按钮可达，消息气泡最大宽度增加以利用窄屏。
- Markdown 图片、表格和代码块只能在消息内部适配或滚动，不推动页面整体宽度。

### 图片编辑器与协同编辑

- 工具栏允许多行换行或局部横向滚动，所有工具按钮保持可点击，不压缩到不可读。
- 裁剪、旋转、缩放、翻转和重置仍沿用现有事件与协同消息，不改变权威状态和权限逻辑。
- 编辑画布是允许横向/纵向内部滚动的明确区域；工具栏、底部保存/取消操作不随画布一起滚走。
- 手机上限制编辑弹层高度并压缩非关键说明，横屏时优先给画布空间。
- 所有仅图标工具提供 `aria-label`/标题，协同连接和只读状态包含文字提示，不能只靠颜色表达。

### 管理员表格与复杂工具栏

- 用户管理和图片审核表格外层提供受控内部滚动作为兜底。
- 手机端将每一行呈现为带字段标签的卡片式记录，隐藏表头但保留语义结构；关键标识、状态和操作始终可见。
- 筛选、批量抓取、以图搜图和审核工具栏按组纵向排列，输入控件取消桌面 `max-width`。
- 编辑/删除、通过/拒绝等操作使用至少 44px 的按钮，危险操作保持确认流程和明显的危险样式。

### 图库分析

- 汇总卡片在手机上为一至两列，图表网格降为单列。
- 图表容器高度与内边距随视口调整，ECharts 使用 `autoresize`，缩减小屏坐标轴标签和图例密度。
- 图表交互同时支持点击/触摸，不依赖 hover；数据为空、加载失败时显示文字状态。
- 图表区域提供可读标题和摘要，颜色不作为唯一的数据区分方式。

## 数据流与状态

- 后端 REST、SSE、WebSocket 请求和响应结构不变。
- 用户登录与管理员判断继续由 `useUserStore()` 提供。
- 新增的移动端状态仅包括抽屉开关、必要的筛选展开状态和局部弹层布局状态，不写入业务 Store。
- 路由变化负责关闭抽屉并恢复页面滚动；视口从手机切回桌面时清理移动抽屉状态。
- 图片列表、空间列表、审核和分析的数据加载逻辑不因断点产生不同请求，避免桌面与手机结果不一致。

## 异常与边界处理

- 异步加载、空数据和错误状态在手机上保留明确文字与恢复入口，不让错误信息被弹层或固定操作栏遮挡。
- 移动抽屉与弹层卸载时必须恢复背景滚动；重复打开/关闭不得遗留 `overflow: hidden`。
- 超长文本、超多标签、长 URL、大图、横图、竖图和无缩略图均不得撑破布局。
- 软键盘弹出时，表单当前字段和提交操作应可通过页面滚动访问。
- 横屏时导航、弹层和编辑器不使用固定像素高度覆盖全部内容。

## 可访问性要求

- 菜单按钮使用 `aria-expanded` 与 `aria-controls`；抽屉具有可识别标题和关闭按钮。
- 图片卡片可通过键盘进入详情，不能只在 `div` 点击事件上工作。
- 表单继续使用可见标签；图标按钮具有可访问名称。
- 焦点顺序与视觉顺序一致，弹层打开后焦点进入弹层，关闭后回到触发按钮。
- 正文和控件文字满足正常文本 4.5:1 的对比度目标。

## 测试与验证

- 使用 Node 原生测试增加响应式源代码契约测试，覆盖 viewport、关键断点、导航抽屉可访问属性、表格移动标签和减少动态效果规则。
- 新增导航行为时先写失败测试，再实现最小逻辑；已有 API/协同测试保持通过。
- 执行 `npm test`、`npm run lint`、`npm run build` 和 `npm run check:bundle`。
- 在 360、390、430、768、1024px 以及手机横屏下逐页检查 13 个路由；验证无页面级横向溢出。
- 对登录态、管理员态和普通用户态分别检查导航入口；对表格、弹层、编辑器、AI 面板和图表执行触控与键盘走查。
- 开启 `prefers-reduced-motion` 并放大浏览器字体，确认内容和操作不被裁切。

## 非目标

- 不修改后端接口、权限规则、协同协议或数据库。
- 不引入新的 UI 框架、图标库、PWA 能力或独立移动端应用。
- 不重做现有品牌、配色与桌面信息架构。
- 不为桌面和手机维护两套独立业务组件。
