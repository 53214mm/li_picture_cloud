# 团队图片只读协同观察设计

## 1. 背景与根因

团队查看者已经拥有 `picture:view`，因此能够在空间图片列表中看到图片。但是图片详情接口仍调用旧的编辑权限校验，要求 `picture:edit`，导致查看者点击图片后收到“缺少权限：picture:edit”，前端又把任何详情请求失败统一展示成“图片不存在或已被删除”。

协同链路也把“加入房间”和“发送操作”混成了一项权限：WebSocket 握手直接要求 `collaboration:edit`。因此查看者既不能发送编辑命令，也不能连接房间接收其他人的实时操作。

## 2. 目标

团队查看者应当能够：

- 打开拥有 `picture:view` 权限的团队图片详情；
- 点击“观看协同”进入只读协同窗口；
- 接收当前旋转角度、缩放比例、后续实时操作和加入/离开提示；
- 看到其他成员执行左旋、右旋、放大、缩小后的效果。

团队查看者不能：

- 在界面执行旋转、缩放或保存替换；
- 通过伪造 WebSocket 消息发送编辑命令；
- 查看自己没有 `picture:view` 权限的图片。

## 3. 选定方案

复用现有协同 WebSocket 房间和图片编辑弹窗，增加明确的只读模式。

没有采用独立观察页面，因为它会重复图片渲染、状态同步和连接管理。也不在图片详情打开时自动连接，因为那会让只是浏览图片的用户都占用 WebSocket。查看者通过“观看协同”主动加入；编辑者继续通过“协同编辑”加入。

## 4. 权限模型

权限职责拆分如下：

| 权限 | 含义 |
| --- | --- |
| `picture:view` | 获取团队图片详情和静态内容 |
| `collaboration:join` | 建立 WebSocket、接收状态和房间事件 |
| `collaboration:edit` | 发送旋转或缩放命令 |
| `picture:edit` | 修改图片资料和保存替换后的图片 |

查看者角色增加 `collaboration:join`，但不增加 `collaboration:edit` 或 `picture:edit`。编辑者与管理员保持现有全部协同权限。

服务端边界：

1. 图片详情接口对空间图片检查 `picture:view`。
2. WebSocket 握手检查 `collaboration:join`。
3. 每一条 WebSocket 操作消息仍检查 `collaboration:edit`。
4. 保存替换图片仍经过 `picture:edit`，不能因进入只读房间而绕过。

即使查看者修改前端代码发送命令，服务端处理器也会拒绝操作并返回错误事件。

## 5. 前端交互

图片详情根据服务端权限展示入口：

- 拥有 `collaboration:edit`：显示“协同编辑”。
- 只有 `collaboration:join`：显示“观看协同”。
- 两者都没有：不显示协同入口。

`ImageEditModal` 增加 `readOnly` 属性：

- 标题显示“观看协同”；
- 连接 WebSocket 并正常应用服务端状态；
- 图片编辑器隐藏或禁用左旋、右旋、放大、缩小操作；
- 不发送 `operation` 事件；
- 隐藏“保存并替换”，底部只保留“关闭”；
- 状态栏显示“只读协同已连接”和最新操作提示。

编辑模式下现有行为不变。

## 6. 错误处理

- 图片真实不存在：仍展示“图片不存在或已被删除”。
- 图片存在但无 `picture:view`：展示后端的“缺少权限：picture:view”，不再伪装成不存在。
- 只读 WebSocket 握手失败：显示“只读协同连接异常”，静态图片详情仍可查看。
- 查看者伪造命令：后端返回“协同操作被拒绝”，不改变权威状态。
- 编辑过程中权限被撤销：下一条命令被拒绝；连接重建时握手也会按最新 `collaboration:join` 判断。

## 7. 测试与验收

后端测试覆盖：

- viewer 可以获取团队图片详情；
- 无 `picture:view` 的用户不能获取详情；
- viewer 可以通过 WebSocket 握手加入协同房间；
- viewer 发送命令仍被 `collaboration:edit` 拒绝；
- editor 继续能够加入并发送命令；
- 角色配置中 viewer 只有 join、没有 edit。

前端测试覆盖只读属性和能力判断：viewer 得到“观看协同”，编辑控件与保存按钮不可用；editor 得到“协同编辑”。最后运行完整 Maven 测试，以及前端 test、lint、build、bundle 和安全审计。

人工验收使用两个账号：编辑者打开协同编辑并连续旋转、缩放；查看者打开同一图片的“观看协同”，应实时看到效果和提示，但无法产生任何编辑命令。
