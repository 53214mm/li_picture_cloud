# 玩法配方工坊设计（第二年第五季度）

> 日期：2026-08-15
>
> 依据：三年规划第五季度（2027-08—2027-10）「玩法配方工坊」；
> 依赖：Q3 模型网关（语言/视觉/图片创作三任务路由 + MCP 白名单 + 试用账本）
> 与 Q4 图片炼金（创作任务、候选、血缘、暂存、回库管线）。

## 1. 目标

在第一年「喂图 → 理解 → 成长 → 记忆 → 对话 → 主动提案 → 创作 → 保存回图库」闭环之上，
让用户**组合而非编码**出属于自己的玩法：用 `WHEN + 最多 5 个 IF + 一个 THEN` 把已审核的
白名单能力拼成配方，官方模板开箱即用。配方只能收紧权限、范围和费用，不能扩大。

## 2. 核心概念

### 2.1 配方 `Recipe`

- `WHEN`：触发条件（如「每周日晚」「图片分类出现旅行」「纪念日」），与 Q2 机会源共享抽象。
- `IF`（0—5 条）：限定条件，全部满足才执行（如「只处理私有空间的图片」「仅用用户 BYOK 连接」）。
- `THEN`：单一动作（如「生成故事草稿」「生成表情候选」「融合图片」），只能是白名单能力之一。

### 2.2 能力白名单

配方可用的能力 = Q3/Q4 已交付能力的**受控子集**：`story_draft`、`emoji_draft`、`image_fusion`。
MCP 工具仍走平台审核 + 逐项启停的白名单，不因配方而放宽。

### 2.3 收紧不扩大（红线）

- 配方只能在执行时**收紧**：图片来源范围、目标空间、可见性、模型成本上限、执行频率。
- 任何配方参数都不得越过能力本身的权限边界（图片 PICTURE_VIEW、空间 PICTURE_UPLOAD、
  试用额度硬上限、BYOK 失败不静默回退）。

### 2.4 版本与回放

- 配方修改产生新版本（append-only），执行记录绑定版本号；停用即时生效。
- 每次执行（试运行或真实执行）留下可回放记录：触发时间、命中条件、费用报价、
  生成任务引用、结果状态；回放只含安全字段，不含图片字节或密钥。

## 3. 领域模型（草案）

- `Recipe`：`id, subjectId, name, status(DRAFT/ENABLED/DISABLED), revision, 时间戳`。
- `RecipeVersion`（append-only）：`recipeId, version, whenTriggerJson, ifConditionsJson, thenActionJson, 时间戳`。
- `RecipeExecution`：`recipeId, version, triggerTime, matchedConditionsJson, costQuoteJson,
  creationTaskId(可空), status(DRY_RUN/EXECUTED/FAILED/REJECTED), safeErrorCode`。
- 执行前报价复用试用账本语义；BYOK 路由失败大声失败并写 REJECTED。

## 4. 与现有系统整合

- 触发：`WHEN` 复用 Q2 机会源（每周回顾/纪念日/相似图片）的调度与契约闸门（自主契约开关、
  频率、安静时段、离线规则）。
- 执行：`THEN` 直接调用现有 `StoryDraftService` / `EmojiDraftService` / `FusionImageService`
  的公开方法，不复制管线。
- 伙伴技能熟练度只影响表达风格与建议质量（如故事语气、候选措辞），绝不绕过能力权限。
- 官方模板：旅行回顾、生日故事、每周表情、旧照重制（每个模板是一个不可编辑系统配方的
  可复制起点）。

## 5. 安全与隐私

- 配方 JSON 校验为白名单键值、只允许安全纯文本；执行时按当前版本重新校验能力与权限。
- 执行记录与回放日志不含图片字节、提示词正文、密钥或用户原文；只保留安全字段。
- 配方费用报价是上限承诺，实际结算不得超出；平台试用账本硬上限继续生效。

## 6. 明确不做

- 不做任意代码执行、任意 Prompt 注入或任意 MCP 工具编排（第二年不开放任意代码）。
- 不做付费配方市场与批量分发（第三年再评估）。
- 配方不得修改他人空间、不得覆盖原图、不得扩大图片或空间权限。

## 7. 验收条件

- 用户能从官方模板出发，在 10 分钟内建成一个自己的配方并完成一次试运行；
- 试运行/执行预览展示命中条件、目标动作与费用报价，确认后才产生真实创作任务；
- 停用配方后不再产生任何新执行；配方版本可追溯、执行可回放；
- 任何配方都无法越过图片/空间权限、试用额度或 BYOK 红线。

## 8. 实施切片建议

1. 规格先行（本文档）+ 领域模型与迁移（recipe / recipe_version / recipe_execution）。
2. 能力白名单 + 配方 JSON 校验器（收紧语义）与官方模板种子。
3. 执行引擎：WHEN 复用机会源 → IF 求值 → 报价 → 调 THEN 服务 → 执行记录与回放。
4. 前端配方工坊页（模板起点、组合编辑、试运行、执行历史回放）。
5. 全链路测试 + E2E + 独立审查。
