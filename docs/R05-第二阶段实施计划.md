## 3. 首发视觉兼容方案（本计划建议）

第一阶段已决定“直接换身体、保留业务生命周期”；**本计划建议首发对已有单实例统一使用 Adult 视觉资源**。这项具体投放方案在 Phase A 规格验收时核定，不是擅自把后端生命周期改为 Adult，也不重新打开已决定的角色 / 技术选型。

| 当前输入 | 首发计划显示 | 保持不变 |
| --- | --- | --- |
| 已加载实例，LIGHT / SEEDLING / COMPANION 任一种 | 绫页 Adult Home / Shell / Portrait；按所在位置选资源 | 原 id、真实 lifeStage、level 与全部业务数据 |
| 已有实例，遇到未知 / 缺省 stage 值 | 稳定 Adult 静态 fallback，不推断新阶段、不编造等级 | 后端值与业务面板的真实状态 |
| Home 尚未加载或请求失败 | 现有加载 / 错误状态，固定占位；不展示假实例、不启动动画 | 重试与业务权限 |
| Home 已返回但无 companion | 现有未唤醒入口；不制造 Egg / 孵化倒计时 | 只有用户原有显式唤醒操作才能创建实例 |
| Shell 无实例数据（当前实际情况） | 绫页静态导航标记 + “伙伴空间”；不表示已拥有、在线或某阶段 | 不新增全局请求 / 轮询，不影响路由权限 |

`currentStage` 表示原后端输入，`visualStage` 仅为本地资源选择。界面 Stats 继续呈现真实阶段，不因 Adult 图片把 LIGHT 改名。现有唤醒 API 返回实例后也可按同一单实例策略显示身体，但不得新增孵化流程。

Egg / Juvenile 方向已经接受，首发可暂不在正式业务里切换。未来新 Species 才实施 Egg → Hatch → Juvenile → Adult；已有伙伴不倒退。若 Phase A 审阅决定扩展首发阶段，需要先给出明确的视觉兼容规则和对应资产验收，不能仅按等级 / 枚举名称自动映射。

## 4. 实施顺序与退出条件

```text
A 资产规格与生产验收 → B 轻量表示层 → C Shell / D Hero / E Portrait 静态接入
                                  ↓
                         F 单一 Idle PoC → 接入 D
G 身份兼容约束贯穿 A～F；静态接入与 Idle 完成后统一回归
                                  ↓
                              H 验证与人工验收
```

按功能单元逐个完成，不要求并行实施。先获得可用静态 fallback，再验证动画。C 的 Shell 首版保持静态，不因为播放器已存在就增加常驻循环。每单元保留可回退的前端变更，不修改业务数据；遇到资产未验收或兼容条件不明时停在该单元，不伪称完成。

### Phase A：资产规格确认与生产准备

**交付**：沿已选方向完成资源规格、独立生产静态素材及来源说明；不继续发散人设。制作前确认规格，制作后验收静态图和第一帧，才能进入静态产品接入。Idle 在 A 中只约定动作 / 锚点并准备候选帧，最终图集与播放验收放在 F，避免以 F 的结果作为 A 的前置条件。

| 最小交付物 | 数量 / 范围 | 验收要求 |
| --- | --- | --- |
| Adult Home 全身静态 | 1 张，正常比例 | 独立透明图，无邻图 / 字母 / 色板；触角、翼、裙摆与鞋完整，统一脚底落点 |
| Adult Shell 简化静态 | 1 张，面向现有 40×44 槽位 | 减纸纹 / 衣褶，保留纸翼与发束等识别点；不改成 Q 版，文字导航始终可读 |
| Adult Neutral Portrait | 1 张，正常比例半身 | 头肩 / 胸部构图，种族特征可见，桌面与手机裁切一致 |
| Expression Diff | 必要时 1～2 张，可不纳入首发加载 | 共用画幅 / 对齐；仅资产能力，不冻结公共状态枚举或自动切换规则 |
| 最小 Idle 候选 | 仅一个短循环，优先眨眼；最终帧数 / 时长 / 图集由 F 验证交付 | 与 Home 静态图一致；第一帧可独立用，脚底不漂移，翼与长衣不跳形 |
| 制作源文件与资源清单 | 一份可编辑母版与清单 | 记录来源、使用权、版本、实际宽高 / 字节、锚点、透明边界、帧时长、fallback |

建议生产资源集中在 `src/assets/companion/lingye/`，资源元信息放在 `src/components/companion/body/lingyeAssets.js`（均为待创建路径）。本地 `lingye` 是资源键，不是新造的 DB speciesId。文件名带版本，禁止覆盖探索档案。

在目标 CSS 显示尺寸上确定源图采样与 DPR：Shell 先验收 40×44，再用 48/64/80px 对照；Home 先确认现有 Hero 的可用区域。不要直接常驻整张 1536×1024 设定页。记录静态图与图集总下载量、解码像素量和画幅；资源预算在 A 中写定，F 用测量结果核对，超出预算就减帧 / 减画幅或回退静态。

**边界**：三阶段设计通过不要求首发生产三套所有动作；Q 版桌宠和 B/C 不生产。可选差分、整间房背景、换装和额外动作均不能成为最小交付的隐性依赖。

### Phase B：轻量 Companion Body 表示层

**拟涉及**：新增 `src/components/companion/body/` 下的 `CompanionBody.vue`、`CompanionPortrait.vue`、`CompanionPresence.vue` 和本地资源清单。文件名可随现有风格小幅调整，不预先建立引擎注册器、插件系统或全局 Renderer Framework。

组件职责：Body 管画框、静态 / Idle 与降级；Portrait 是正常比例中性半身的薄封装；Presence 负责小尺寸静态图。业务页面仍拥有真实 Companion 数据与接口调用。

| 输入（概念接口，非 R06 协议） | 用途与限制 |
| --- | --- |
| representation | shell / home / portrait 等本地显示位置；不表达业务行为 |
| currentStage | 原后端 stage 或未知；由集中视觉适配规则选资产，不写回 |
| fallback | 首帧 / 静态资源；全部失败时为中性占位与现有文字导航，避免失败递归 |
| accessibleLabel / decorative | Home / Portrait 可读标签；Shell 图片在有链接文字时作为装饰，避免重复朗读 |
| paused / visible / animate | 只控制绘制生命周期，不含 Mood、Feed、Chat、Proposal 状态机 |

未来多 Species 或 Live2D / Spine 只替换此边界之后的资源 / 显示实现。首版不要求 `speciesId`，不从身体组件获取全局伙伴列表、不创建 Displayed store、不提前冻结 expression / action 公共枚举。

**验收**：资源选择集中；同一输入的 fallback 可预测；页面不散布 `/lingye.png`；图片失败仍保留可访问标签、尺寸和导航；不会触发业务写请求。对有回归风险的阶段 / 降级规则先写行为测试，再实现；不为静态样式机械增加测试。

### Phase C：替换 Shell 的抽象身体标记

**拟修改**：CompanionPresenceSlot.vue；必要时仅局部调整 AppLayout.vue 的显示 / 暂停透传。

1. 在原 40×44 标记容器内使用简化静态 Sprite，保留 router-link、aria-current、文字、焦点环及最小点击区域。
2. 保持 224px 桌面栏 / 88px 平板栏 / 手机底栏与抽屉行为，不引入角色选择器或悬浮宠物，不扩大侧栏挤压导航。
3. 处理侧栏和抽屉的重复入口；不可见副本不启动绘制循环、不预取 Home 图集或 Portrait。首版静态 Shell 不读取或猜测实例在线状态。
4. 保留 feature flag 和 Overlay / Modal inert；角色不越过弹层接收点击。关闭功能时没有角色图片请求、播放器或新 Companion API 请求。

**验收**：导航与键盘、断点、滚动和焦点恢复继续可用；图片加载前后槽位几何一致，无布局跳动、图像越界或导航遮挡。

### Phase D：Companion Home 主体接入

**拟修改**：CompanionView.vue 中的 `.life-orbit` 主体与对应局部样式。

1. 只在真实 `home.companion` 存在时接入绫页 Body，复用页面现有 home 读取和刷新，不新建全局 Companion store。
2. 使用正常比例全身和稳定脚底锚点，局部设置留白 / 地面承托；只调整主视觉区域，不照搬 HTML 原型重建整个小屋。
3. 保持 authError、featureUnavailable、loadError、pageLoading、未唤醒入口；不在 mounted 时调用唤醒、Feed 或其他写接口。
4. 保留 Stats、Feed、Mood、Relationship、Chat、Proposal、Memory、Story、Emoji、Fusion、Growth 的既有能力与布局顺序；必要的 Hero 文案只解释身体，不能伪造经历。

**验收**：Adult 宽翼不挡业务按钮，窄屏不挤压正文；加载 / 失败 / 未唤醒均真实。身体失败不影响 Feed、记忆和聊天，Feed 后权威 home 刷新仍工作。

### Phase E：Conversation Portrait

**拟修改**：CompanionChatPanel.vue，以及 CompanionView.vue 的局部 props 传递。

1. 添加一处稳定 Portrait 展示，不在每条流式消息旁重复挂载大图；桌面半身、手机缩略，文本与输入优先。
2. 接收当前实例已有展示信息 / currentStage，不重复请求 home、不改变 history、stream、重试、草稿恢复或滚动逻辑。
3. 首版 Neutral。可选表情差分只验证资源与对齐；没有可信表现状态时不自动切换，不按“哈哈”或其他关键词猜测，不把 sending 当作新的 thinking 协议。
4. 图像失败回到中性占位，聊天输入与响应状态正常；alt 不能宣称模型看到图片、已经生成记忆或已执行 Proposal。

**验收**：输入焦点、历史阅读、发送 / 错误恢复及窄屏滚动保持；换 Portrait 不改变对话内容或 Companion 身份。表情状态集与 Mood / Interaction Result → Expression 留给 R06 / R11。

### Phase F：最小 Sprite PoC 与一个 Idle

**拟新增**：body 目录内极小 `SpritePlayer.vue`，必要时一个负责暂停 / 清理的 composable；优先 CSS `steps()` 等原生路径。若实际帧时长不等才评估小型计时播放器，不安装 Pixi / Live2D / Spine。

只验证一个短 Idle（眨眼、轻呼吸或翼缘微动择最小可行项），不做 Walk / Sleep / Feed / Chat / Proposal 动作、转场队列、优先级或完整状态机。PoC 结果决定 N 帧及其时长，不能把示例帧数变成先验验收标准。

必须实现并验证：

- 暂停输入与最小暂停 / 恢复控制；Home 动画不能没有用户可用的停止方式。
- `document.hidden` 时暂停；不可见 / 卸载时停止调度，返回后尊重原暂停状态，不补跑后台积累的帧。
- `prefers-reduced-motion`（含运行时变化）使用静态第一帧，不以“减慢”替代；初次加载和图集失败也保留静态 fallback。
- Overlay / Modal 打开、宿主不可交互时停止主动动画；不改变原弹层层级。
- 卸载清理 timer / rAF、visibility / media query 监听与 observer（仅对实际使用者）；重复进入页面不叠加调度。
- 所有帧统一尺寸与脚底，避免触角 / 翼 / 长衣跳变；图集播放异常可以关掉 Idle 退静态，不能让业务失败。

**记录与退出条件**：记录图集下载字节、像素解码估算、冷加载 / 首帧时间、Idle 帧时间、后台恢复及多次挂卸载的资源变化；写明浏览器、设备和不可测项。只通过了静态接入而 Idle 未通过时，标记 F 未完成并回退静态供审阅，不宣称 Sprite 动画已验收。

### Phase G：旧伙伴身份与数据兼容

**拟涉及**：B 的本地视觉适配函数和 D / E 输入；现有后端、SQL、API 均不改。

第一 Species / 绫页只作为单实例时代的默认 Representation 解释，不写入虚构 speciesId，不提供 displayedCompanionId。该策略不是未来多 Species 的最终数据模型。

使用已有不同真实阶段的测试实例覆盖 LIGHT / SEEDLING / COMPANION，比较展示前后 companionId、owner、lifeExperience、level、lifeStage、Traits、Mood、Relationship、Memory、Feed 历史与 Proposal / Contract 的持久化数据；身体展示本身零业务写请求。不重新创建、认领、孵化、清空或重算任何历史。

读取 Mood 时可能存在既有时间衰减，验证应固定测试时钟 / 数据或比较持久化事实及写请求，不能把自然时间变化误判成身体重置。原有 Feed / Chat / Proposal 的用户显式操作照常执行，各自测试结果不混同为“展示导致写入”。

**验收**：所有旧阶段都能获得身体，旧 LIGHT 仍能聊天和 Feed；不存在 / 未加载不造实例；业务阶段和关系记忆不因 Representation 切换变化。未来 Owned / Displayed 分离的约束保留在角色体系，不在本单元编码。
