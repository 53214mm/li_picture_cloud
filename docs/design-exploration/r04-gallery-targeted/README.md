## 对照公平性与使用

- 同一 DOM、记录、图片顺序、标题、作者、日期、标签、查询、页码、每页 12 张；切换只改版本 class / 状态文案，不重新抽样或翻页，尽量恢复切换前 scrollY（接近文档末尾可能被新文档高度限住）。
- 同一个简化 R02 Shell：桌面 224px、平板 88px 侧栏；68/60px 顶栏、手机底栏；同一个 legacy `.container` 宽度与 gutter。不是 Kimi 的替代 Shell，也不是完整正式 Shell 像素复刻。普通登录用户场景，不额外放管理员上传按钮。
- 模拟声明集中于页尾，不塞到每张卡片。8 张本地图片生成 120 条数据，日期精确到天。格式筛选字段为模拟，不代表文件本身被转码。
- 两态均可输入“山间水岸”（名称）或“清晨”（只在简介）搜索；分类、格式、排序、标签可以组合。标签同时满足，选“自然+人物”产生无结果，清除后恢复 120 条。
- 页数输入 8 + Enter 应显示 1085–1096 的记录（标题序号 085–096），输入 10 + GO 到最后一页 1109–1120；页码超限夹到 1–10，非数字回 1。手机跳页需切到定向改良态。
- 验证工具提供 loading / list error / first-image error / 1:12 长条 fixture。长条是内存 SVG 几何测试图，不是外部素材；其它图仍来自仓库。
- 点击图片只显示目标路径提示，不创建查看器，不访问真实路由/API。页内示意链接未实现真实详情往返状态，URL 同步等属于后续工程。

## Kimi “图片太长”核查：未复现，不能宣布根因

已核对源码 `../r04-gallery-kimi/index.html`：

- 第 381 行是 `span.ph > img`；第 138–142 行 `.ph` 设置 aspect-ratio:4/3，但正常态没有 display:block/flex/grid 或明确 width/height。第 149 行仅失败态设置 display:flex。
- 第 41 行 img 为 block；第 143–147 行 img 为 width/height:100%、cover。这些声明不能单独证明容器最终 4:3，也不能证明百分比 height 有确定参照。
- 第 154–157 行 t-info 在图下，名称、元信息各有自己的行高；它们会参与卡片纵向排版，但最终增加多少高度尚未测量。t-info 自身也是 span，不能把 10px padding 简单当成稳定块级高度相加。
- 需要验证的链条：普通 inline span 没有建立受 ratio 约束的图片盒 → img 百分比高度参照不定 / 自然尺寸参与尺寸计算 → 高图片可能抬高 Grid 行；另有图下两行信息增加卡片高度。**这只是与源码吻合的风险假设，不是已通过浏览器证实的根因。**
- 实际尝试：浏览器工具导航至指定 Kimi 本地 HTML 被 URL 安全策略拒绝。未采用服务器、其它浏览器、CDP 等绕过。遵循 diagnosing-bugs 的证据要求，复现、bounding box、computed display/height、对照改变 display 后的因果验证均**未执行**。
- 建议人工在相同视口记录 `.tile/.ph/img/.t-info` 的 display、实际宽高、aspectRatio 和 gridTemplateRows；仅临时改变 ph 的 display 后重测，才能区分容器失效与信息下移的贡献。即使证实并修复盒子问题，也不代表信息下移或 Viewer 获认可。本轮不改 Kimi 原型。

### 本地测量入口

在实际浏览器设置 1440×900 / 390×844（是网页 viewport，不是窗口外框）后，清空条件、回第 1 页，在“验证工具”点击“测量两态”。它会：

1. 保持同一组数据和页码，依次临时显示两态并回到页顶；隐藏原型工具条、排除 hover 位移影响。
2. 读取实际 bounding box：列数、画框比例、首图 y、首屏完整/部分候选、下一行可见张数/高度、网格高度、最后一项文档 y、横向溢出、元信息实际字号/透明度、首图自然/渲染尺寸。
3. 首屏计数扣除相同 Shell 顶栏/手机底栏；输出到只读文本框，随后恢复原版本和 scrollY。该输出只有点击执行后才存在，不预填样本数值。

此入口本身尚未浏览器实测。截图仍需实际浏览器捕获；未包含自动截图权限或远程上传。请同时检查文字可读性，数字检查不能替代用户视觉判断。
