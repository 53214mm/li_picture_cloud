# R05 — 世界观骨架（第一阶段已收口）

日期：2026-09-23。第一阶段世界观骨架已确认；不是已上线剧情或全部地点玩法承诺。第一位伙伴正式采用绫页 / 纸翼蛾族，Egg / Juvenile / Adult 视觉方向均已接受。生产资产另行准备。

## 1. 一扇窗和一处住址

世界暂称「雾屿」。它是一片有海岸、林地和小聚落的群岛，居民具有不同的幻想生物形态。纸、布、木、陶和贝壳是常见材料。魔法表现在材料如何留住光、声音和痕迹，不表现为遍地霓虹法阵。

第一位伙伴住在「留影小屋」的一间屋子里。这里有采光窗、可以坐下的低台、一张桌和少量空架。小屋是自己的生活场所，图库仍是用户的资产空间。进入 `/companion` 的感受应该是去看她，而不是打开一套宠物管理后台。

用户是与她建立联系的另一端。用户通过 Feed 主动选择并确认「把这张图片给她看」，才像把一小片现实景色递过窗来。上传、打开或预览图片都不代表分享。图片不被消耗，也不会按画面内容实时重绘身体；未来达到已确认的成长条件时，可以切换到该 Species 对应阶段的官方身体资产。

这扇窗是界面隐喻，不是现实门户或新网络协议。功能未开启时，不暗示她在后台偷看、等候或记住用户。没有真实事件时，不显示「刚旅行回来」等事实台词。

## 2. 未来新伙伴的蛋与当前伙伴的身体

这些种族以「眠卵」开始生命：壳上的材料结构已经包含种族特征，里面尚未形成可与用户完整交流的身体。官方未来提供获得某种蛋的机会；获得方式不在 R05 制定。

未来新 Species 获得蛋时建立唯一伙伴实例，Egg → Hatch → Juvenile → Adult 都是同一实例的成长过程；具体获取与生命周期持久化另做领域设计。官方设定可以说某种族来自海岸或林地，不能给所有实例预写完全相同的「我曾和你旅行」的记忆。模板传递文化、身体与性格倾向；具体人生在实例中发生。

当前已有的光团伙伴直接获得绫页身体，是「已有伙伴终于获得正式身体」。原 companionId、owner、成长、lifeStage、Traits、Mood、Relationship、Memory、Feed 与 Proposal / Contract 全部延续，不创建新伙伴、不认领身份、不重新孵化。旧 LIGHT 即使等级低也可能已交流与形成记忆，不能显示成失去交流能力的蛋。

第二阶段保留 LIGHT / SEEDLING / COMPANION，身体资产的视觉阶段不改变真实业务阶段。接受三种视觉方向，不等于首版必须展示三个阶段，也不要求老伙伴重走一遍人生。

卵不是可堆叠的重复角色材料。用户不能持有 A×17，也没有稀有度、十连抽、突破或合成。新物种的加入，是认识另一种伙伴的机会。

## 3. 审美如何连接 R01

R01 的暖纸 `#f6f4ef`、表面 `#fcfbf8`、文字 `#211e1a`、雾蓝 `#47618c` 来自现有 [tokens.css](../li-picture-cloud-frontend/src/styles/tokens.css)。角色借用材料和光线，不必把所有头发与衣服染成雾蓝。

| 层次 | 约束 |
| --- | --- |
| UI | 暖纸底、雾蓝交互、细边界；不为每个角色换整站主题 |
| 场景 | 暖灰木材、浅墙、低对比窗光；不在首版铺高饱和 RPG 地图 |
| 人物 | 2 个主体色块 + 1 个少量强调色，脸和种族轮廓保持明确对比 |
| 共同纹样 | 偏移的画框缺角、层叠边缘；只选一个位置表达，不做遍身品牌水印 |
| 材质 | 纸翼、贝壳、陶鳞各自有特性，线条与阴影层次保持同一画风 |
| Shell | 背景最简，减少纹理；不靠发光、红点、摇晃争夺图库注意力 |

「缺角」只是候选美术语法，不保证天然独占或已具商标辨识度。需要后续去 Logo 识别测试、相似性检查与正式命名核查。

| 地点候选 | 以后可能发生什么 | 本轮承诺 |
| --- | --- | --- |
| 留影小屋 | 休息、放照片、与用户相处 | 只验证角色尺度与留白 |
| 林缘 / 田野 | 捡到叶片、观察季节 | 一个未来地点标识与美术氛围 |

| 市集 | 看见手作品、交换故事 | 不创建货币、商店、NPC 或任务 |
| 山间陶窑 / 矿地 | 观察材料、带回碎片 | 不创建采集、背包或生产玩法 |

未来可借鉴「她有自己的生活、用户回来看看」的时间感，但不在 R05 虚构自主行程或建立后台 Tick 系统。没有在今天调用外部游戏资料来证明其具体玩法；这里只使用用户已给定的参考方向，角色美术不引用其角色资产。

## 5. 图片、解释和共同经历

同一张城堡图可以产生三种不同来源：

1. **Observation**：「画面里有一座城堡。」只描述真正看到的内容；元数据路径不能假装看过像素。
2. **User Context**：「这是我和朋友在 MC 里建的。」是用户明确补充的背景，需要保留归因。
3. **Shared Experience**：「我们聊过为了屋顶返工三次。」必须来自真实发生的互动，后续事件若引用也要可追溯。

城堡图不证明用户住在城堡、去过当地或偏好中世纪建筑。记忆候选、用户确认与长期可引用事实仍由现有记忆边界控制。未来三类来源不能仅通过一个渲染器布尔值实现。

成长与记忆并行：某次 Feed 可以有成长而没有可信视觉记忆；视觉失败或元数据降级不应被台词包装成「我看到了」。图片被撤权或删除后的记忆传播规则继续沿用现有权限边界，换身体不能绕过。

## 6. 关系支持变化，也容纳分歧

角色具有稳定的关注点与说话节奏，但不能永远开心、永远迎合或把「主人」作为唯一关系脚本。她可以对图片内容好奇、对不确定的结论追问，也可以安静。

两个用户养成同种角色，会保留相似的视觉身份和人格核心；共同经历、熟悉程度、喜欢谈的话题与表达习惯会不同。官方个性不是用预置值覆盖现有 Traits 的理由。

长时间不回来不构成道德过错。不通过孤独值威胁用户，不用连续签到或喂养焦虑推动留存。用户选择少分享图片时，这段关系仍应成立。

## 7. Home 的空间方向与首版边界

隔离原型使用固定构图、小屋留白与地面落点探索同住感；这些比例不是正式 Vue 页面验收尺寸。第二阶段只在现有 CompanionView 的主视觉区域替换光团，按绫页宽翼与正常比例预留脚底和包围盒，不重做整间房或 R09。身体不遮挡 Feed、导航与业务按钮。

照片架只表示未来可以放经用户选择的内容；空架可以保持为空，不自动复制私有图库。纪念品的位置是未来扩展槽，不意味着已有背包或旅行物品。

桌面 Shell 是小屋门口的一小段栖居位；Home 是全身；Conversation 是靠近说话时的半身视角。首版分别使用简化 Sprite、全身 Sprite 与静态 / 表情差分 Portrait。未来 Q 版桌宠也只是同一 Instance 的另一种 Representation，不产生新的记忆所有者。

## 8. 多位伙伴真实存在，前台展示只选一位

长期关系借鉴用户提出的首页助理展示与多角色生活空间：只借鉴展示关系，不复制《明日方舟》的 UI、美术、文案或角色。Owned Companion 是用户实际拥有的全部实例；Displayed Companion 只表示当前 Shell / 首页 / 全局 Presence 主要展示谁。

将展示对象由绫页切换成另一位伙伴，不删除、不替换或重置绫页的成长、关系、记忆与生活状态。未来 Home 可以呈现绫页在窗边、另一位在桌边、某位外出的不同存在状态；这些状态必须来自真实系统事实，当前不得伪造。

Displayed Companion ≠ Only Companion。本轮仅记录该约束，第二阶段仍支持已有单实例；不制作多伙伴 Home、选择器、角色轮换或 displayedCompanionId。数据边界见[角色体系 Architecture Notes](R05-角色体系设计.md#9-architecture-notes未来-owned-与-displayed)。
