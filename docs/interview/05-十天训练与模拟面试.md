# LiPictureCloud 十天训练与模拟面试

> 目标岗位：Java 后端实习 / 校招。每天 5～6 小时。目标不是十天背完全部八股，而是做到：项目讲得清、核心原理说得出、不会的问题能诚实收口。

## 一、每天固定节奏

| 时段 | 用时 | 做什么 |
| --- | ---: | --- |
| 复习 | 30 分钟 | 不看答案，复述昨天的 5 个问题 |
| 主课 | 120 分钟 | 阅读指定章节，写知识卡 |
| 源码 | 90 分钟 | 沿入口追调用链，画一张图 |
| 口述 | 60 分钟 | 录音回答，不允许默读答案 |
| 八股 | 60 分钟 | 完成当天 Java/Spring/MySQL 题 |
| 复盘 | 30 分钟 | 记录卡壳点，按红黄绿标记 |

每天结束必须产出三样东西：一张手绘流程图、一段 3～5 分钟录音、五张问答卡。只看文档不算完成。

## 二、十天冲刺日程

### Day 1：把项目从数据库讲到接口

**学习目标：** 不看 README，也能解释用户、图片、空间、成员四个核心实体和一次请求的完整路径。

- 必读：[项目全流程与自我介绍](01-项目全流程与自我介绍.md)的自我介绍、领域模型、通用请求链。
- 源码：`Picture`、`Space`、`SpaceUser` 实体；`PictureController`；`PictureServiceImpl`。
- 画图：ER 图；浏览器 → Nginx → Controller → Service → Mapper → MySQL。
- 口答：项目解决什么问题？为什么不只是 CRUD？Controller、Service、Mapper 各负责什么？
- 八股：ArrayList/LinkedList、HashMap、equals/hashCode、B+Tree 索引。

**过关标准：** 2 分钟介绍无明显停顿；能从一个接口定位到数据库表；不把 DTO、VO、Entity 混为一谈。

### Day 2：图片上传、对象存储与分析

**学习目标：** 讲清文件流、元数据、COS 与 MySQL 的一致性边界，以及分析查询的数据来源。

- 必读：[项目全流程](01-项目全流程与自我介绍.md)中的上传、分析流程；[追问题库](04-项目追问题库.md) Q2、Q10。
- 源码：`PictureController`、`PictureServiceImpl`、上传模板类、`SpaceAnalyzeServiceImpl`。
- 画图：上传成功、COS 成功但数据库失败两条分支。
- 口答：`@Transactional` 为什么不能回滚 COS？如何补偿？分析页“暂无数据”如何分层排查？
- 八股：事务 ACID、隔离级别、MVCC、覆盖索引、慢 SQL 排查。

**过关标准：** 主动说出外部资源不受本地事务控制；能区分“接口空数据”“前端参数错误”“旧静态包”。

### Day 3：权限、AOP 与 Spring MVC

**学习目标：** 讲清登录认证、资源授权、权限注解和异常响应，不把“登录了”当成“有权限”。

- 必读：[核心技术补课](02-核心技术补课.md)的 Spring MVC、Spring Boot、权限章节。
- 源码：权限注解、权限拦截器、`SpaceUserAuthManager`、全局异常处理器。
- 画图：HTTP 请求经过 Filter、DispatcherServlet、Interceptor/AOP、Controller 的顺序。
- 口答：认证与授权区别？为什么后端仍要校验？AOP 如何读取注解？异常怎样变成统一响应？
- 八股：IOC、AOP、动态代理、Bean 生命周期、事务失效、自动装配。

**过关标准：** 能用 60 秒解释 Spring Boot 自动装配；能指出前端隐藏按钮不是安全边界。

### Day 4：WebSocket 与实时协同

**学习目标：** 真正理解连接升级、握手鉴权、房间会话、命令处理和广播。

- 必读：[核心技术补课](02-核心技术补课.md)的 WebSocket、Redis Pub/Sub；[追问题库](04-项目追问题库.md) Q3～Q5。
- 源码：`CollaborationWebSocketConfig`、握手拦截器、`CollaborationWebSocketHandler`、事件发布与订阅类。
- 画图：用户 A 命令 → 实例 1 → Redis → 实例 2 → 用户 B。
- 口答：HTTP 如何升级为 WebSocket？为什么 viewer 能加入但不能编辑？为何不把 `WebSocketSession` 存 Redis？
- 八股：TCP 与 HTTP 基础、线程安全集合、ConcurrentHashMap、ThreadLocal。

**过关标准：** 不再说“两个对象通过消息队列通信”；能区分长连接、状态存储和跨实例事件三件事。

### Day 5：Redis Lua、幂等与缓存

**学习目标：** 能逐段解释协同 Lua 的输入、返回值和原子性边界。

- 必读：[核心技术补课](02-核心技术补课.md)的 Redis Lua；[追问题库](04-项目追问题库.md) Q6、Q13。
- 源码：`collaboration-apply.lua`、`RedisCollaborationStateStore`、缓存读写代码。
- 画图：APPLIED、DUPLICATE、CONFLICT 三条分支。
- 口答：Lua 为什么原子？commandId 和 baseVersion 分别解决什么？Pub/Sub 丢消息怎么办？
- 八股：缓存穿透、击穿、雪崩、双写一致性、Redis 持久化与过期策略。

**过关标准：** 能承认 Lua 只保证单次 Redis 脚本执行原子，不夸大成全系统强一致。

### Day 6：ShardingSphere 分表

**学习目标：** 从“完全不懂”提升到能讲清为什么做、如何路由、有什么限制。

- 必读：[核心技术补课](02-核心技术补课.md)的静态分表、动态算法和关闭方式；[追问题库](04-项目追问题库.md) Q7。
- 源码：静态/动态 YAML、`DynamicPictureShardingAlgorithm`、相关测试。
- 画图：逻辑表 `picture` 按分片键路由到真实表。
- 口答：分库与分表区别？为什么要分片键？跨分片查询有什么代价？动态算法会自动建表吗？
- 八股：JOIN 类型、执行计划、索引失效、分页优化。

**过关标准：** 明确线上是否默认开启；绝不虚构数据量；能说出分表增加的复杂度。

### Day 7：AI Agent、MCP 与用户上下文

**学习目标：** 把你的优势讲深，重点讲请求级用户隔离和真实故障修复。

- 必读：[项目全流程](01-项目全流程与自我介绍.md)的 AI 流程；[追问题库](04-项目追问题库.md) Q8、Q9。
- 源码：`PicCloudApp`、AI Controller、意图识别、MCP 图片保存工具、上下文回归测试。
- 画图：用户消息 → 意图 → Agent → ToolCallback → MCP → COS/MySQL → SSE。
- 口答：记忆、知识库、工具调用各解决什么？为什么共享回调数组导致用户串线？如何验证修复？
- 八股：浅拷贝/深拷贝、共享可变状态、线程池参数、异常体系。

**过关标准：** 能用“现象—根因—修复—测试”完整讲 AI 图片错归管理员的 Bug。

### Day 8：Java 集合、并发与 JVM 保命日

**学习目标：** 覆盖校招高频基础，先做到能答 60 秒。

- 必读：[Java 与框架高频保命题](03-Java与框架高频保命题.md)前 24 题。
- 源码联系：协同房间集合、线程上下文、异常处理、异步任务。
- 画图：HashMap put；线程池工作流程；JVM 运行时区域；类加载双亲委派。
- 口答：HashMap、ConcurrentHashMap、volatile、CAS、死锁、GC Roots、OOM。
- 练习：随机抽 15 题，每题 60 秒，录音后删除口头禅。

**过关标准：** 15 题至少 11 题达到“定义 + 原理 + 项目联系”，不会时能给出边界。

### Day 9：Spring、事务、MySQL 与 Redis 串联

**学习目标：** 从单点背诵升级为一次请求中的组合解释。

- 必读：[Java 与框架高频保命题](03-Java与框架高频保命题.md)剩余题目。
- 画图：Spring Bean 创建；代理事务调用；MySQL MVCC；缓存旁路模式。
- 口答：自动装配、事务自调用失效、MVCC、JOIN、缓存一致性、Redis 降级。
- 故障题：NOAUTH、CI exit 126、线上旧前端包分别如何定位。
- 快问：完成[30 题快速问答](04-项目追问题库.md#九30-题快速问答先别往下看答案)。

**过关标准：** 快问 30 题答对 24 题；故障题先取证再改代码。

### Day 10：两轮全真面试与最终收口

**学习目标：** 在压力下保持结构、真实性和节奏。

- 上午：完成“友好一面”，按评分表复盘并补红色卡片。
- 下午：完成“项目深挖面”或请朋友照脚本追问。
- 晚上：完成“压力面”，然后重录 2 分钟项目介绍。
- 最终材料：2 分钟介绍、一个最有价值 Bug、一个技术难点、一个不足与改进计划。

**过关标准：** 两轮均达到 70 分；没有虚构线上数据；任何不会的问题能在 20 秒内诚实收口。

## 四、模拟面试一：友好型一面（45 分钟）

### 面试官脚本

1. 请做 1 分钟自我介绍。
2. 介绍最熟悉的项目，它解决了什么问题？
3. 一次图片上传是怎样完成的？
4. 团队空间如何做权限控制？
5. WebSocket 和普通 HTTP 有什么不同？
6. Redis 在项目中分别做了什么？
7. HashMap 和 ConcurrentHashMap 有何区别？
8. Spring Boot 为什么加注解就能工作？
9. MySQL 索引为何使用 B+Tree？
10. 你遇到的最有价值 Bug 是什么？

### 追问分支

- 上传：COS 成功而数据库失败怎么办？
- 权限：viewer 如何看协同却不能编辑？
- Redis：缓存不可用时系统是否还能服务？
- Bug：如何证明根因，而不是碰巧修好？

### 答案指南

每题按“结论 → 项目流程 → 原理 → 边界”回答。项目题引用[项目全流程](01-项目全流程与自我介绍.md)，基础题引用[保命题](03-Java与框架高频保命题.md)。本轮重点不是刁难，而是检查基础表达。

## 五、模拟面试二：项目深挖面（60 分钟）

### 面试官脚本

1. 为什么说它不是普通 CRUD？
2. 画出协同编辑从 A 到 B 的完整链路。
3. Redis Lua 的键、参数、返回状态是什么？
4. 两个后端实例如何同步？订阅者重启会怎样？
5. 查看者伪造编辑消息，在哪一层被拒绝？
6. 分表的逻辑表、真实表和分片键分别是什么？
7. 为什么没有默认开启动态分表？
8. AI 生图为什么曾全部进入管理员空间？
9. 个人图库分析为空，你如何定位？
10. 如果并发和数据量增长十倍，先改什么？

### 追问分支

- 协同：重复 commandId、旧 baseVersion、Pub/Sub 丢失分别怎样处理？
- AI：为什么不是 Redis 串数据？测试如何模拟两个用户？
- 分表：跨分片分页、扩容、建表由谁负责？
- 扩容：先用监控证据找瓶颈，不接受“所有组件都上集群”。

### 答案指南

以[核心技术补课](02-核心技术补课.md)和[追问题库](04-项目追问题库.md)为准。答不出实现细节时，打开对应源码入口复盘；答不出原理时，不要用项目现象冒充通用结论。

## 六、模拟面试三：压力面（45 分钟）

### 面试官脚本

1. 这项目是不是 AI 写的？你究竟做了什么？
2. 数据量并不大，为什么加分表，是不是堆技术？
3. Pub/Sub 不可靠，凭什么说支持协同？
4. Lua 就几行脚本，技术难点在哪里？
5. 你连 Spring 自动装配都说不清，为什么招你？
6. 线上出现过哪些问题？哪个是你的责任？
7. 如果现在让你不用 AI 写 JOIN，能写吗？
8. 你最薄弱的三个知识点是什么？两周如何补？

### 合格回答原则

- 不防御、不撒谎：承认 AI 是开发工具，同时说明本人负责需求拆解、方案取舍、验证和复盘。
- 不包装规模：分表是可切换学习与验证能力，线上未默认开启，不声称解决了不存在的流量问题。
- 不回避缺点：Pub/Sub 不做永久日志，客户端需以权威状态重同步；更强可靠性可选 Stream/Kafka。
- 不装懂：JOIN 先写出表关系和连接条件，复杂语法可查文档，但要能解释结果集和索引考虑。

### 压力面评分

每题 5 分：事实准确 2 分、结构 1 分、边界 1 分、情绪稳定 1 分。8 题达到 28 分即过关。

## 七、卡壳时的“保命”话术

### 原理没背熟

> 这个原理我目前掌握得不够完整，我先说项目里真实使用到的部分：……。它解决的是……，边界是……。更底层的实现我面试后会结合源码补齐，不在这里猜。

### 没亲手从零实现

> 这部分我使用 AI 辅助生成过初稿，但需求拆解、关键设计、源码审查和测试验证由我完成。我能沿着实际调用链解释它，也能说明我当时做错和修正的地方。

### 被质疑过度设计

> 以当前数据量它不是必须项，所以我把它设计成可关闭的 Profile，没有作为线上规模成果宣传。它的价值主要是验证路由、分片键和迁移边界；若追求最小生产复杂度，我会先保持单表并用指标决定何时拆分。

### 完全不会

> 这个问题我现在不会。我能想到需要先确认的条件是……，然后会从日志/指标/源码的……位置取证。暂时不直接给结论，避免把猜测当答案。

## 八、面试前一晚与当天

前一晚只复习：2 分钟介绍、五条核心流程、十个红色问题、两个真实 Bug。不要熬夜再开新知识点。

面试当天：提前测试网络和麦克风；桌边放一张实体关系图和关键词纸；每题停一秒再回答。不会一两题很正常，面试官更关注你是否能把会的内容讲清、是否可信、是否具有补课能力。

完成十天后，回到[冲刺使用指南](00-冲刺使用指南.md)重新给全部知识点标色；仍为红色的内容就是下一轮训练清单。
