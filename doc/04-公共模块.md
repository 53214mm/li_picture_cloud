# 公共模块

## 一、模块概述

公共模块为全项目提供统一的基础设施：API 响应格式、异常处理机制、分页基类、JSON 序列化配置、CORS 策略和 MyBatis-Plus 插件配置。

## 二、响应体体系 — `BaseResponse<T>` + `ResultUtils`

### 2.1 BaseResponse 源码

```java
@Data
public class BaseResponse<T> implements Serializable {

    private int code;        // 业务状态码：0=成功，非0=各种错误
    private String message;  // 提示信息：成功时 "ok"，失败时为具体错误描述
    private T data;          // 泛型数据载荷

    // 全参构造（code + message + data）
    public BaseResponse(int code, String message, T data) {
        this.code = code;
        this.message = message;
        this.data = data;
    }

    // 无 data 构造（用于错误响应）
    public BaseResponse(int code, String message) {
        this(code, message, null);
    }

    // 无 message 构造
    public BaseResponse(int code, T data) {
        this(code, "", data);
    }

    // 从 ErrorCode 枚举构造
    public BaseResponse(ErrorCode errorCode) {
        this(errorCode.getCode(), errorCode.getMessage(), null);
    }
}
```

### 2.2 ResultUtils 快捷构造

```java
public class ResultUtils {

    /** 成功响应 */
    public static <T> BaseResponse<T> success(T data) {
        return new BaseResponse<>(0, "ok", data);        // code=0, message="ok"
    }

    /** 通过 ErrorCode 枚举构造错误 */
    public static BaseResponse<?> error(ErrorCode errorCode) {
        return new BaseResponse<>(errorCode);
    }

    /** 通过自定义 code + message 构造错误 */
    public static BaseResponse<?> error(int code, String message) {
        return new BaseResponse<>(code, message);
    }

    /** 通过 ErrorCode + 自定义 message 构造错误（重写默认消息） */
    public static BaseResponse<?> error(ErrorCode errorCode, String message) {
        return new BaseResponse<>(errorCode.getCode(), message);
    }
}
```

### 2.3 使用模式

```java
// Controller 中的典型用法
@GetMapping("/current")
public BaseResponse<UserVO> getCurrentUser(HttpServletRequest request) {
    UserVO loginUser = userService.getLoginUser(request);
    return ResultUtils.success(loginUser);
    // 前端收到：{ "code": 0, "message": "ok", "data": { UserVO } }
}

// 失败场景
throw new BusinessException(ErrorCode.NOT_LOGIN_ERROR);
// 全局异常处理器捕获后返回：
// { "code": 40100, "message": "未登录", "data": null }
```

## 三、错误码枚举 — `ErrorCode`

```java
@Getter
public enum ErrorCode {

    SUCCESS           (0,     "ok"),
    PARAMS_ERROR      (40000, "请求参数错误"),
    NOT_LOGIN_ERROR   (40100, "未登录"),
    NO_AUTH_ERROR     (40101, "无权限"),
    FORBIDDEN_ERROR   (40300, "禁止访问"),
    NOT_FOUND_ERROR   (40400, "请求数据不存在"),
    SYSTEM_ERROR      (50000, "系统内部异常"),
    OPERATION_ERROR   (50001, "操作失败");

    private final int code;       // 数字错误码
    private final String message; // 默认提示信息
}
```

错误码采用 5 位数字编码，前 3 位对应 HTTP 状态码的语义：

| 区间 | 含义 | 示例 |
|------|------|------|
| 0 | 成功 | `SUCCESS(0)` |
| 40000-40999 | 客户端错误 | `PARAMS_ERROR(40000)`, `NOT_LOGIN_ERROR(40100)` |
| 50000-50999 | 服务端错误 | `SYSTEM_ERROR(50000)`, `OPERATION_ERROR(50001)` |

## 四、异常体系

### 4.1 BusinessException

```java
@Getter
public class BusinessException extends RuntimeException {       // ★ 继承 RuntimeException（非受检异常）
    private final int code;

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    public BusinessException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.code = errorCode.getCode();
    }

    public BusinessException(ErrorCode errorCode, String message) {
        super(message);                                          // 自定义 message 覆盖默认
        this.code = errorCode.getCode();
    }
}
```

继承 `RuntimeException` 的设计用意：
1. 业务异常不需要在方法签名中声明 `throws`（非受检异常）
2. Spring 默认只对 `RuntimeException` 及其子类触发事务回滚

### 4.2 ThrowUtils — 条件抛出快捷工具

```java
public class ThrowUtils {

    /** 条件为 true 时抛出指定异常 */
    public static void throwIf(boolean condition, RuntimeException exception) {
        if (condition) throw exception;
    }

    /** 条件为 true 时抛出 BusinessException（使用 ErrorCode 的默认 message） */
    public static void throwIf(boolean condition, ErrorCode errorCode) {
        throwIf(condition, new BusinessException(errorCode));
    }

    /** 条件为 true 时抛出 BusinessException（自定义 message） */
    public static void throwIf(boolean condition, ErrorCode errorCode, String message) {
        throwIf(condition, new BusinessException(errorCode, message));
    }
}
```

使用效果：

```java
// 不用 ThrowUtils（3 行）
if (userRegisterRequest == null) {
    throw new BusinessException(ErrorCode.PARAMS_ERROR, "请求参数为空");
}

// 用 ThrowUtils（1 行）
ThrowUtils.throwIf(userRegisterRequest == null, ErrorCode.PARAMS_ERROR, "请求参数为空");
```

### 4.3 GlobalExceptionHandler — 全局异常捕获

```java
@Slf4j
@RestControllerAdvice                     // ★ = @ControllerAdvice + @ResponseBody
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public BaseResponse<?> handleBusinessException(BusinessException e) {
        log.error("业务异常: code={}, message={}", e.getCode(), e.getMessage());
        return ResultUtils.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(Exception.class)
    public BaseResponse<?> handleException(Exception e) {
        log.error("系统异常: ", e);                              // 打印完整堆栈
        return ResultUtils.error(ErrorCode.SYSTEM_ERROR.getCode(), "系统内部异常");
    }
}
```

**工作流程**：当 Controller 抛出任何未被 catch 的异常时，Spring MVC 会遍历 `@ExceptionHandler` 注解的方法，找到匹配的处理器执行。

**优先级**：子类匹配优先。`BusinessException` 被第一个 handler 捕获，其他所有异常（如 `NullPointerException`、`IOException`）被第二个 handler 兜底。

**安全性**：对外返回的是固定的"系统内部异常"，不暴露内部错误细节，但日志中保留了完整堆栈供开发者排查。

## 五、分页基类 — `PageRequest`

```java
@Data
public class PageRequest {

    private int current = 1;             // 当前页码，默认第 1 页
    private int pageSize = 10;           // 每页大小，默认 10 条
    private String sortField;            // 排序字段名（对应数据库列名）
    private String sortOrder = "descend"; // ascend = 升序, descend = 降序
}
```

所有需要分页查询的请求 DTO 继承此类：

```java
// UserQueryRequest 继承 PageRequest，自动获得分页和排序能力
public class UserQueryRequest extends PageRequest {
    private String userAccount;
    private String userName;
    // ...
}

// PictureQueryRequest 同样继承
public class PictureQueryRequest extends PageRequest {
    private String searchText;
    private String category;
    // ...
}
```

## 七、配置类详解

### 7.1 CorsConfig — 跨域策略

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")                      // 覆盖所有 API 路径
                .allowCredentials(true)                  // ★ 允许携带 Cookie（Session 认证需要）
                .allowedOriginPatterns("*")              // ★ 允许所有来源
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .exposedHeaders("*");
    }
}
```

**重要**：`allowCredentials(true)` 与 `allowedOrigins("*")` 不能同时使用（浏览器安全策略），因此这里用 `allowedOriginPatterns("*")`——这是一个通配符模式匹配，不与 Cookie 冲突。

### 7.2 JacksonConfig — Long 序列化为 String

```java
@Configuration
public class JacksonConfig {

    @Bean
    public Jackson2ObjectMapperBuilderCustomizer longToStringCustomizer() {
        return builder -> {
            // Long 包装类型 → String
            builder.serializerByType(Long.class, ToStringSerializer.instance);
            // long 基本类型 → String
            builder.serializerByType(Long.TYPE, ToStringSerializer.instance);
        };
    }
}
```

**解决的问题**：

```
雪花 ID 示例：1823456789012345678

JavaScript 中：
JSON.parse('{"id": 1823456789012345678}')
// → { id: 1823456789012345700 }  ← 精度丢失！末尾数字变了

启用 JacksonConfig 后 JSON 变为：
{"id": "1823456789012345678"}
// → { id: "1823456789012345678" }  ← 字符串，精度完整
```

JavaScript 的 Number 类型基于 IEEE 754 双精度浮点数，最大安全整数为 `2^53 - 1 = 9007199254740991`（约 16 位）。雪花 ID 为 18-19 位，超出此范围。

### 7.3 MyBatisPlusConfig — 分页插件

```java
@Configuration
public class MyBatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        PaginationInnerInterceptor paginationInterceptor =
            new PaginationInnerInterceptor(DbType.MYSQL);   // 指定数据库方言
        paginationInterceptor.setMaxLimit(100L);             // ★ 单页最大 100 条

        interceptor.addInnerInterceptor(paginationInterceptor);
        return interceptor;
    }
}
```

**如果不注册此 Bean**：调用 `this.page(page, wrapper)` 时不会自动追加 `LIMIT` 子句，导致全表扫描后由 MyBatis-Plus 在内存中截取（性能灾难）。

**`setMaxLimit(100L)`**：安全保护——即使前端传 `pageSize=99999`，实际查询也最多返回 100 条。

## 九、启动类 — `LiPictureCloudApplication`

```java
@SpringBootApplication
@MapperScan("com.li.lipicturecloud.mapper")          // ★ 扫描 Mapper 接口
@EnableAspectJAutoProxy(exposeProxy = true)          // ★ 启用 AOP 代理
public class LiPictureCloudApplication {
    public static void main(String[] args) {
        SpringApplication.run(LiPictureCloudApplication.class, args);
    }
}
```

| 注解 | 作用 |
|------|------|
| `@SpringBootApplication` | 组合 `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan` |
| `@MapperScan("com.li.lipicturecloud.mapper")` | 扫描指定包下的 MyBatis-Plus Mapper 接口并生成代理实现 |
| `@EnableAspectJAutoProxy(exposeProxy = true)` | 启用 AOP（`@AuthCheck` 的拦截依赖于此），`exposeProxy = true` 允许通过 `AopContext.currentProxy()` 获取当前代理对象 |
