# 图库分析模块

## 一、模块概述

图库分析模块提供空间和公共图库的多维度数据统计，包括使用概览、分类分布、标签热度、大小分布、上传趋势和空间排行。前端使用 ECharts 可视化展示。

### 访问路径

- 后端 API 前缀：`POST /api/space/analyze/*`
- 前端路由：`/space/analyze` → `SpaceAnalyzeView.vue`
- 导航栏入口：「图库分析」

---

## 二、后端 API

### 2.1 空间使用分析

```
POST /space/analyze/usage
```

**请求体**（继承 SpaceAnalyzeRequest）：
```json
{
  "spaceId": 1823456789012345678,   // 指定空间（三选一）
  "queryPublic": true,              // 或：查询公共图库
  "queryAll": true                  // 或：查询全部空间（管理员）
}
```

**响应**：
```json
{
  "usedSize": 10485760,        // 已使用大小（字节）
  "maxSize": 104857600,        // 最大容量（公共图库为 null）
  "sizeUsageRatio": 10.0,      // 容量使用率（%）
  "usedCount": 25,             // 当前图片数量
  "maxCount": 100,             // 最大数量
  "countUsageRatio": 25.0      // 数量使用率（%）
}
```

### 2.2 分类分析

```
POST /space/analyze/category
```

返回图片按分类（category）分组统计。

**响应**：`List<{ category, count, totalSize }>`

### 2.3 标签分析

```
POST /space/analyze/tag
```

返回所有标签按使用次数降序排列（JSON 标签反序列化后合并统计）。

**响应**：`List<{ tag, count }>`

### 2.4 大小分布

```
POST /space/analyze/size
```

按文件大小分段统计图片数量：`<100KB` / `100KB-500KB` / `500KB-1MB` / `>1MB`。

**响应**：`List<{ sizeRange, count }>`

### 2.5 用户上传趋势

```
POST /space/analyze/user
```

**额外参数**：
```json
{
  "timeDimension": "day",    // day | week | month
  "userId": 123              // 可选，筛选特定用户
}
```

**响应**：`List<{ period, count }>` — period 格式取决于 timeDimension

### 2.6 空间排行

```
POST /space/analyze/rank
```
需要管理员权限。

**请求**：`{ "topN": 10 }` — 取前 N 名

**响应**：`List<Space>` — id, spaceName, userId, totalSize 按 totalSize 降序

## 三、前端图表

| 图表 | ECharts 类型 | 数据源 |
|------|-------------|--------|
| 使用概览 | 统计卡片 ×4 | `/usage` |
| 分类分布 | 环形饼图 (pie) | `/category` |
| 大小分布 | 环形饼图 (pie) | `/size` |
| 热门标签 | 横向柱状图 (bar) Top 20 | `/tag` |
| 上传趋势 | 折线面积图 (line) | `/user` |
| 空间排行 | 横向柱状图 (bar) Top 15 | `/rank` |

### 交互设计

- 顶部范围切换：**我的空间** / **公共图库** / **全部空间**（管理员）
- 我的空间模式下可选择具体空间
- 上传趋势支持 **日/周/月** 时间维度切换
- 管理员可见空间排行面板

## 五、代码审查发现

后端代码整体结构清晰，权限校验到位。以下为审查中发现的问题：

### 已修复

无严重 bug，代码可直接使用。

### 潜在改进

| # | 问题 | 建议 |
|---|------|------|
| 1 | `getSpaceRankAnalyze` 中 `topN` 无上限校验 | 建议限制 `topN ≤ 100`，防止一次性拉取全量数据 |
| 2 | `getSpaceUserAnalyze` 中 `timeDimension` 校验仅靠 switch default | 建议在入口处明确校验 `day/week/month`，避免 SQL 拼接错误 |
| 3 | `fillAnalyzeQueryWrapper` 为 static 方法 | 方法内部未使用实例字段，static 正确但无法 mock。如需测试可改为实例方法 |
| 4 | 标签分析中 `JSONUtil.toList` 对非法 JSON 可能抛异常 | 建议 try-catch 包裹，跳过无法解析的 tags 字段 |
