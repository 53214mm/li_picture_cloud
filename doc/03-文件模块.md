# 文件模块

## 一、模块概述

文件模块是系统的底层能力支撑层，负责与腾讯云 COS（对象存储）的交互、文件格式和大小的校验、临时文件的管理以及图片元信息的提取。

### 架构职责划分

```
PictureController（Controller 层）
  └── PictureServiceImpl（Service 层）
        └── FileManager（Manager 层 — 文件业务编排）
              ├── validPicture()        文件校验（大小 ≤ 2MB，格式白名单）
              ├── 创建临时文件           MultipartFile → java.io.File
              ├── CosManager（Manager 层 — COS SDK 封装）
              │     └── COSClient       腾讯云 COS Java SDK
              │           └── 腾讯云 COS 云端存储
              └── deleteTempFile()      清理临时文件（finally 块保证执行）
```

**Manager 层的价值**：Controller 不直接接触 COS SDK，Service 不处理文件校验细节。两层 Manager 各自承担清晰职责——`CosManager` 封装第三方 SDK，`FileManager` 编排文件业务逻辑。

## 三、CosClientConfig — COS 客户端配置

```java
@Configuration
@ConfigurationProperties(prefix = "cos.client")   // ★ 自动绑定 YAML 中的 cos.client.* 属性
@Data                                               // Lombok：为 host/secretId/…生成 getter/setter
public class CosClientConfig {

    private String host;        // COS 访问域名
    private String secretId;    // 腾讯云 API 密钥 ID
    private String secretKey;   // 腾讯云 API 密钥 Key
    private String region;      // COS 区域（如 ap-beijing）
    private String bucket;      // COS 存储桶名称

    @Bean
    public COSClient cosClient() {
        // 1. 构造腾讯云认证信息
        COSCredentials cred = new BasicCOSCredentials(secretId, secretKey);

        // 2. 设置 COS 区域
        ClientConfig clientConfig = new ClientConfig(new Region(region));

        // 3. 生成并注册 COS 客户端 Bean（单例，全局共用）
        return new COSClient(cred, clientConfig);
    }
}
```

**`@ConfigurationProperties(prefix = "cos.client")`** 的工作原理：

```yaml
# application-local.yaml
cos:
  client:
    host: https://xx-li-p...
    secretId: AKIDIgroY4N...
    secretKey: PaXEgjYM3Z...
    region: ap-beijing
    bucket: xx-li-picture...
```

Spring Boot 启动时自动将上述 YAML 属性注入到 `CosClientConfig` 的同名字段中（通过 setter 方法，由 Lombok `@Data` 生成）。`cosClient()` 方法上的 `@Bean` 标注使其返回值被 Spring 容器管理为一个单例 Bean。

### 4.2 普通文件上传 — `putObject()`

```java
    public PutObjectResult putObject(String key, File file) {
        PutObjectRequest putObjectRequest = new PutObjectRequest(
            cosClientConfig.getBucket(),   // bucket 名称
            key,                            // 对象键（COS 中的文件路径）
            file                            // 本地文件
        );
        return cosClient.putObject(putObjectRequest);
    }
```

### 4.3 文件下载 — `getObject()`

```java
    public COSObject getObject(String key) {
        GetObjectRequest getObjectRequest = new GetObjectRequest(
            cosClientConfig.getBucket(), key
        );
        return cosClient.getObject(getObjectRequest);
    }
```

### 4.4 图片上传并提取元信息 — `putPictureObject()`

```java
    public PutObjectResult putPictureObject(String key, File file) {
        PutObjectRequest putObjectRequest = new PutObjectRequest(
            cosClientConfig.getBucket(), key, file
        );

        // ★ 核心：通过 PicOperations 让 COS 在上传时返回图片信息
        PicOperations picOperations = new PicOperations();
        picOperations.setIsPicInfo(1);       // 1 = 返回原图信息（宽度/高度/格式等）
        putObjectRequest.setPicOperations(picOperations);

        return cosClient.putObject(putObjectRequest);
    }
```

**`PicOperations.setIsPicInfo(1)`** 是 COS 万象（CI）能力的入口——上传文件后，COS 会在响应中附带该图片的元数据（宽度、高度、格式、颜色模式等），无需额外请求。这比"上传后再调一个接口获取图片信息"高效得多。

上传后返回的 `PutObjectResult` 中可提取：

```java
ImageInfo imageInfo = putObjectResult.getCiUploadResult()
                                     .getOriginalInfo()
                                     .getImageInfo();
// imageInfo.getWidth()     → 图片宽度
// imageInfo.getHeight()    → 图片高度
// imageInfo.getFormat()    → 图片格式 (jpg/png/webp)
```

### 5.2 核心上传方法 — `uploadPicture()` 逐段讲解

```java
    public UploadPictureResult uploadPicture(MultipartFile multipartFile, String uploadPathPrefix) {
```

#### Step 1 — 前置校验

```java
        validPicture(multipartFile);        // 校验大小和格式（见 5.3 节）
```

#### Step 2 — 生成唯一上传路径

```java
        String uuid = RandomUtil.randomString(16);            // 16 位随机字符串
        String originFilename = multipartFile.getOriginalFilename();
        String uploadFilename = String.format("%s_%s.%s",
            DateUtil.formatDate(new Date()),                  // 日期：20260613
            uuid,                                              // 随机字串
            FileUtil.getSuffix(originFilename)                 // 扩展名：jpg
        );
        String uploadPath = String.format("/%s/%s", uploadPathPrefix, uploadFilename);
```

生成结果示例：`/public/1823456789012345678/20260613_a3f8b2c1d4e5f6a7.jpg`

`RandomUtil.randomString(16)` 使用 Hutool 生成 16 位随机字符串，配合日期前缀保证同名文件概率极低。

#### Step 3 — MultipartFile 转临时文件

```java
        File file = null;
        try {
            file = File.createTempFile(uploadPath, null);     // 创建临时文件
            multipartFile.transferTo(file);                  // 将上传内容写入临时文件
```

`MultipartFile` 是 Spring 对 HTTP multipart 上传的抽象，不能直接传给 COS SDK（SDK 需要 `java.io.File`），因此必须先通过 `createTempFile` + `transferTo` 创建一个临时文件。

#### Step 4 — 上传到 COS 并提取图片信息

```java
            PutObjectResult putObjectResult = cosManager.putPictureObject(uploadPath, file);
            ImageInfo imageInfo = putObjectResult.getCiUploadResult()
                                                  .getOriginalInfo()
                                                  .getImageInfo();
```

#### Step 5 — 构造返回结果

```java
            UploadPictureResult uploadPictureResult = new UploadPictureResult();

            int picWidth = imageInfo.getWidth();
            int picHeight = imageInfo.getHeight();
            double picScale = NumberUtil.round(picWidth * 1.0 / picHeight, 2).doubleValue();
            // NumberUtil.round(value, 2)：四舍五入保留 2 位小数

            uploadPictureResult.setPicName(FileUtil.mainName(originFilename));   // 不含扩展名的文件名
            uploadPictureResult.setPicWidth(picWidth);
            uploadPictureResult.setPicHeight(picHeight);
            uploadPictureResult.setPicScale(picScale);                            // 如 1.78
            uploadPictureResult.setPicFormat(imageInfo.getFormat());
            uploadPictureResult.setPicSize(FileUtil.size(file));
            uploadPictureResult.setUrl(cosClientConfig.getHost() + "/" + uploadPath);
            // url 示例：https://xx-...cos.ap-beijing.myqcloud.com/public/123/20260613_xxx.jpg

            return uploadPictureResult;
```

#### Step 6 — 异常处理与 finally 清理

```java
        } catch (Exception e) {
            log.error("图片上传到对象存储失败", e);
            throw new BusinessException(ErrorCode.SYSTEM_ERROR, "上传失败");
        } finally {
            this.deleteTempFile(file);      // ★ finally 保证临时文件一定被清理
        }
    }
```

### 5.3 文件校验 — `validPicture()`

```java
    public void validPicture(MultipartFile multipartFile) {
        ThrowUtils.throwIf(multipartFile == null, ErrorCode.PARAMS_ERROR, "文件不能为空");

        // ===== 大小校验 =====
        long fileSize = multipartFile.getSize();
        final long ONE_M = 1024 * 1024L;
        ThrowUtils.throwIf(fileSize > 2 * ONE_M, ErrorCode.PARAMS_ERROR, "文件大小不能超过 2M");

        // ===== 格式校验（白名单模式） =====
        String fileSuffix = FileUtil.getSuffix(multipartFile.getOriginalFilename());
        final List<String> ALLOW_FORMAT_LIST = Arrays.asList("jpeg", "jpg", "png", "webp");
        ThrowUtils.throwIf(!ALLOW_FORMAT_LIST.contains(fileSuffix),
                           ErrorCode.PARAMS_ERROR, "文件类型错误");
    }
```

**为什么用白名单而不是黑名单？** 安全最佳实践：只允许已知安全的格式，拒绝一切未知格式。如果用黑名单（"不允许 exe/sh"），新型攻击格式需要不断更新黑名单才能防御。

### 5.4 临时文件清理 — `deleteTempFile()`

```java
    public void deleteTempFile(File file) {
        if (file == null) return;

        boolean deleteResult = file.delete();               // java.io.File.delete()
        if (!deleteResult) {
            log.error("file delete error, filepath = {}", file.getAbsolutePath());
        }
    }
```

清理失败不抛异常——仅记录日志。因为此时上传已经成功（或已经失败），临时文件清理不应影响业务主流程。

```java
public void testDownloadFile(String filepath, HttpServletResponse response) throws IOException {

    try {
        COSObject cosObject = cosManager.getObject(filepath);

    }
}
```

## 八、两层文件大小限制

项目中存在两层大小限制，分别作用于不同层面：

| 层级 | 配置 | 限制值 | 作用范围 |
|------|------|--------|----------|
| Spring Multipart | `application.yaml` 中的 `spring.servlet.multipart.max-file-size` | 10MB | 全局所有上传请求 |
| FileManager 校验 | `validPicture()` 方法硬编码 | 2MB | 仅图片上传业务 |

**为什么有两层？** Spring 的配置是框架级硬限制（超过 10MB 直接拒绝），FileManager 的校验是业务级限制（图片不应超过 2MB）。业务规则更严格，可以在上传前给出友好的中文错误提示。

## 九、临时文件的生命周期

```
createTempFile()  →  transferTo()  →  COS SDK 上传  →  deleteTempFile()
     │                    │                  │                │
  创建 .tmp        写入上传内容       读取文件上传云端      删除 .tmp
```

- `File.createTempFile()` 在系统临时目录创建文件（Windows: `%TEMP%`，Linux: `/tmp`）
- 无论上传成功还是失败，`finally` 块中的 `deleteTempFile()` 都会执行
- 如果 JVM 异常退出，临时文件由操作系统的临时目录清理机制兜底

## 十、COS 对象键命名规范

```
{uploadPathPrefix}/{date}_{16位随机}.{ext}

示例：
public/1823456789012345678/20260613_a3f8b2c1d4e5f6a7.jpg
```

- `uploadPathPrefix`：由 Service 层传入，格式为 `public/{userId}`，按用户划分目录
- `date`：`DateUtil.formatDate(new Date())` 输出 `yyyyMMdd` 格式
- `16位随机`：`RandomUtil.randomString(16)` 输出字母数字混合字符串
- `ext`：从原始文件名的后缀提取（如 `jpg`、`png`）

这样设计的优点：
1. 按用户分目录 → 方便按用户统计存储量、批量操作
2. 日期前缀 → 方便按时间归档
3. 16 位随机字符串 → 文件名极难碰撞（62^16 种可能）

## 十一、模板方法模式重构（v2）

### 11.1 设计动机

原有的 `FileManager` 仅支持 `MultipartFile` 上传。新增 URL 上传功能后，两种上传方式共享大量重复逻辑（生成路径 → 创建临时文件 → 上传 COS → 提取元数据 → 构造结果 → 清理临时文件），差异仅在"校验规则"和"如何将数据写入临时文件"。

使用**模板方法模式**将公共流程提升到抽象父类，子类只需实现 3 个抽象方法：

### 11.2 类图

```
PictureUploadTemplate (abstract)
├── validPicture(Object)         # abstract — 校验输入源
├── getOriginFilename(Object)    # abstract — 获取原始文件名
├── processFile(Object, File)    # abstract — 处理输入源 → 临时文件
│
├── uploadPicture(Object, String)  # ★ final — 模板方法，定义完整上传流程
├── buildResult(...)               # private — 构造 UploadPictureResult
└── deleteTempFile(File)           # public — 清理临时文件
        │
        ├── FilePictureUpload (implements valid/get/process for MultipartFile)
        └── UrlPictureUpload  (implements valid/get/process for String URL)
```

### 11.3 模板方法核心流程

```java
// PictureUploadTemplate.java
public final UploadPictureResult uploadPicture(Object inputSource, String uploadPathPrefix) {
    validPicture(inputSource);                    // 1. 子类实现：文件格式/大小校验 vs URL 可达性校验
    String originFilename = getOriginFilename(inputSource);  // 2. 获取文件名
    String uploadPath = buildUploadPath(uploadPathPrefix, originFilename); // 3. 生成唯一路径

    File file = null;
    try {
        file = File.createTempFile(uploadPath, null);
        processFile(inputSource, file);          // 4. 子类实现：transferTo vs downloadFile
        PutObjectResult result = cosManager.putPictureObject(uploadPath, file);  // 5. 上传 COS
        return buildResult(originFilename, file, uploadPath, imageInfo);         // 6. 封装结果
    } finally {
        deleteTempFile(file);                    // 7. always 清理
    }
}
```

```java
@Service
public class UrlPictureUpload extends PictureUploadTemplate {
    // 校验：URL 格式 → 协议检查 → HEAD 请求验证文件存在 → Content-Type 白名单 → 文件大小
    protected void validPicture(Object inputSource) {
        String fileUrl = (String) inputSource;
        new URL(fileUrl);                         // 验证 URL 格式
        // HEAD 请求检查 Content-Type 和 Content-Length
        HttpResponse response = HttpUtil.createRequest(Method.HEAD, fileUrl).execute();
        // ... type + size checks
    }

    // 处理：下载 URL → 临时文件
    protected void processFile(Object inputSource, File file) throws Exception {
        HttpUtil.downloadFile((String) inputSource, file);
    }
}
```

### 11.6 Service 层的策略选择

```java
// PictureServiceImpl.java
@Resource
private PictureUploadTemplate filePictureUpload;   // Bean "filePictureUpload" → FilePictureUpload
@Resource
private PictureUploadTemplate urlPictureUpload;    // Bean "urlPictureUpload" → UrlPictureUpload

public PictureVO uploadPicture(Object inputSource, ..., User loginUser) {
    PictureUploadTemplate template = filePictureUpload;   // 默认文件上传
    if (inputSource instanceof String) {
        template = urlPictureUpload;                      // URL 上传
    }
    UploadPictureResult result = template.uploadPicture(inputSource, uploadPathPrefix);
    // ... 构造 Picture 实体
}
```

`@Resource` 按字段名匹配 Bean：`filePictureUpload` → `FilePictureUpload` 实例，`urlPictureUpload` → `UrlPictureUpload` 实例。
