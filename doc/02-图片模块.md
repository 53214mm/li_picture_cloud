# 图片模块

## 一、模块概述

图片模块是系统的核心业务模块，负责图片的**上传（COS + 入库）、多条件查询筛选、信息编辑、删除**。图片文件存储在腾讯云 COS，元数据存储在 MySQL 中，通过 `PictureVO` 视图对象关联上传者信息。

### 核心设计决策

1. **存储分离**：图片文件 → COS（高可用、CDN 加速），元数据 → MySQL（支持复杂查询和排序）
2. **三级画质分层**：缩略图（256px，列表快速加载）→ webp 压缩图（高清展示）→ 原图（原始格式，下载用）
3. **JSON 标签**：`tags` 字段在数据库中存储为 JSON 数组字符串（`["风景","建筑"]`），VO 中转为 `List<String>`——兼顾数据库简单性和前端易用性
4. **双接口模式**：管理员接口返回原始 `Picture` 实体，公开接口返回 `PictureVO`（含关联 `UserVO`）
5. **更新机制**：上传接口传入 `id` 即为更新已有图片元数据（覆盖上传），不传则为新增
6. **多级缓存**：Caffeine 本地缓存 → Redis 分布式缓存 → MySQL 数据库，版本号机制保证写入即时失效

## 三、数据库表 — `picture`


### 4.2 实体 ↔ VO 转换方法

```java
// ★ Picture → PictureVO：tags 从 JSON 字符串反序列化为 List
public static PictureVO objToVo(Picture picture) {
    if (picture == null) return null;
    PictureVO pictureVO = new PictureVO();
    BeanUtils.copyProperties(picture, pictureVO);
    pictureVO.setTags(JSONUtil.toList(picture.getTags(), String.class));
    return pictureVO;
}

// ★ PictureVO → Picture：tags 从 List 序列化为 JSON 字符串
public static Picture voToObj(PictureVO pictureVO) {
    if (pictureVO == null) return null;
    Picture picture = new Picture();
    BeanUtils.copyProperties(pictureVO, picture);
    picture.setTags(JSONUtil.toJsonStr(pictureVO.getTags()));
    return picture;
}
```

`JSONUtil.toList()` 和 `JSONUtil.toJsonStr()` 来自 Hutool，分别负责 JSON 数组字符串的反序列化和序列化。例如：

```
数据库存储：   "[\"风景\",\"城市\",\"夜景\"]"
VO 中的 List：  ["风景", "城市", "夜景"]
```

## 六、查询筛选 — `getQueryWrapper()` 深度解析

这是系统的核心查询方法，将前端的各种筛选条件转换为数据库 SQL 的 WHERE 子句。

```java
@Override
public QueryWrapper<Picture> getQueryWrapper(PictureQueryRequest pictureQueryRequest) {
    QueryWrapper<Picture> queryWrapper = new QueryWrapper<>();
    if (pictureQueryRequest == null) return queryWrapper;

    // ===== 跨字段模糊搜索 =====
    String searchText = pictureQueryRequest.getSearchText();
    if (StrUtil.isNotBlank(searchText)) {
        queryWrapper.and(qw -> qw
            .like("name", searchText)          // 名称包含关键词
            .or()
            .like("introduction", searchText)  // 或 简介包含关键词
        );
    }
```

`and()` 方法创建嵌套条件，相当于 `AND (name LIKE '%keyword%' OR introduction LIKE '%keyword%')`，确保搜索词同时匹配名称和简介。

```java
    // ===== 精确匹配 =====
    queryWrapper.eq(ObjUtil.isNotEmpty(id), "id", id);
    queryWrapper.eq(ObjUtil.isNotEmpty(userId), "userId", userId);
    queryWrapper.eq(ObjUtil.isNotEmpty(picWidth), "picWidth", picWidth);
    queryWrapper.eq(ObjUtil.isNotEmpty(picHeight), "picHeight", picHeight);
    queryWrapper.eq(ObjUtil.isNotEmpty(picSize), "picSize", picSize);
    queryWrapper.eq(ObjUtil.isNotEmpty(picScale), "picScale", picScale);
    queryWrapper.eq(StrUtil.isNotBlank(category), "category", category);
```

`eq(condition, column, value)` 中的 condition 是短路开关：当用户没有传入该字段时（值为 null 或空），此条件被自动跳过，SQL 中不会出现该筛选。

```java
    // ===== 模糊匹配 =====
    queryWrapper.like(StrUtil.isNotBlank(name), "name", name);
    queryWrapper.like(StrUtil.isNotBlank(introduction), "introduction", introduction);
    queryWrapper.like(StrUtil.isNotBlank(picFormat), "picFormat", picFormat);
```

```java
    // ===== JSON 数组标签查询 =====
    if (CollUtil.isNotEmpty(tags)) {
        for (String tag : tags) {
            queryWrapper.like("tags", "\"" + tag + "\"");
        }
    }
```

`tags` 在数据库中存储为 `["风景","城市","夜景"]`，查询时用 `LIKE '%"风景"%'` 匹配 JSON 数组中的元素。注意用 `\"` 包裹标签名避免误匹配（如搜索"风"不会匹配到"风景"）。

```java

        StrUtil.isNotEmpty(sortField),
        sortOrder.equals("ascend"),    // ascend → ASC，descend → DESC
        sortField
    );
    return queryWrapper;
}
```

## 七、图片 VO 分页查询 — `getPictureVOPage()`

```java
@Override
public Page<PictureVO> getPictureVOPage(Page<Picture> picturePage, HttpServletRequest request) {
    List<Picture> pictureList = picturePage.getRecords();
    Page<PictureVO> pictureVOPage = new Page<>(picturePage.getCurrent(),
                                                picturePage.getSize(),
                                                picturePage.getTotal());
    if (CollUtil.isEmpty(pictureList)) return pictureVOPage;

    // 1. Entity → VO 转换
    List<PictureVO> pictureVOList = pictureList.stream()
            .map(PictureVO::objToVo)
            .collect(Collectors.toList());

    // 2. ★ 批量关联查询用户信息（避免 N+1 查询）
    Set<Long> userIdSet = pictureList.stream()
            .map(Picture::getUserId)
            .collect(Collectors.toSet());
    Map<Long, List<User>> userIdUserListMap = userService.listByIds(userIdSet)
            .stream()
            .collect(Collectors.groupingBy(User::getId));

    // 3. 填充每个 PictureVO 的 user 字段
    pictureVOList.forEach(pictureVO -> {
        Long userId = pictureVO.getUserId();
        User user = null;
        if (userIdUserListMap.containsKey(userId)) {
            user = userIdUserListMap.get(userId).get(0);
        }
        pictureVO.setUser(userService.getUserVO(user));   // User → UserVO
    });

    pictureVOPage.setRecords(pictureVOList);
    return pictureVOPage;
}
```

**性能要点**：先收集所有 `userId` → 一次性 `listByIds()` 批量查询 → 按 userId 分组为 Map → 循环中直接取用。避免了在 for 循环中逐条查询用户信息（N+1 问题）。

### 8.7 批量图片抓取 — `uploadPictureByBatch()`

管理员可从必应图片搜索批量抓取图片入库：

```
POST /picture/upload/batch
{ "searchText": "风景壁纸", "count": 10, "offset": 0, "namePrefix": "风景" }
```

**流程图**：
```
searchText + count + offset
  → URL 编码搜索词 + first 偏移参数
  → Jsoup 请求必应异步搜索接口 (cn.bing.com/images/async?q=xxx&first=N)
  → 解析 HTML：document.getElementsByClass("dgControl") → select("img.mimg")
  → 遍历 img 标签，调用 extractOriginalUrl() 提取原图 URL
  → 逐个调用 UrlPictureUpload 模板上传到 COS + 入库
  → 每张间隔 500~1500ms 随机延迟（反爬）
  → 单张失败不影响整体，继续处理下一张
  → 返回实际成功数
```

**原图 URL 提取策略**（`extractOriginalUrl()`）：

```java
private String extractOriginalUrl(Element imgElement) {
    // 策略 1：从父级 a.iusc 的 m 属性 JSON 中提取 murl（原图直链）
    Element aTag = imgElement.parent();
    if (aTag != null && "a".equals(aTag.tagName()) && aTag.hasClass("iusc")) {
        String mAttr = aTag.attr("m");
        JSONObject json = JSONUtil.parseObj(mAttr);
        String murl = json.getStr("murl");          // murl 即为原图直链
        if (StrUtil.isNotBlank(murl)) return murl;
    }

    // 策略 2：回退 — 读取 src/data-src，替换 Bing 缩略图 pid 参数
    String src = imgElement.attr("data-src");
    if (StrUtil.isBlank(src)) src = imgElement.attr("src");
    // pid=15.1（最模糊）→ pid=1.1（最高分辨率）
    if (src.contains("bing.net/th")) src = src.replaceFirst("pid=[\\d.]+", "pid=1.1");
    return src;
}
```

**offset 参数**：`first=N` 控制必应图片搜索的偏移量，避免每次抓取重复的图片。前端可传入不同的 offset 值获取不同的图片批次。

**反爬策略**：Chrome User-Agent 模拟 + 随机延迟 500~1500ms + 中断响应处理

## 九、数据校验 — `validPicture()`

```java
@Override
public void validPicture(Picture picture) {
    ThrowUtils.throwIf(picture == null, ErrorCode.PARAMS_ERROR);

    Long id = picture.getId();
    String url = picture.getUrl();
    String introduction = picture.getIntroduction();

    ThrowUtils.throwIf(ObjUtil.isNull(id), ErrorCode.PARAMS_ERROR, "id 不能为空");

    if (StrUtil.isNotBlank(url)) {
        ThrowUtils.throwIf(url.length() > 1024, ErrorCode.PARAMS_ERROR, "url 过长");
    }
    if (StrUtil.isNotBlank(introduction)) {
        ThrowUtils.throwIf(introduction.length() > 800, ErrorCode.PARAMS_ERROR, "简介过长");
    }
}
```

校验规则：`id` 必填（更新操作时），`url` ≤ 1024 字符，`introduction` ≤ 800 字符。

### 10.1 多级缓存机制 — `/list/page/vo/cache`

```java
@PostMapping("/list/page/vo/cache")
public BaseResponse<Page<PictureVO>> listPictureVOByPageWithCache(...) {
    // 1. 构造缓存 key（含版本号，版本递增时旧缓存自然失效）
    String cacheKey = String.format("listPictureVOByPage:v%d:%s", version, md5Hash);
    String redisKey = String.format("lipicturecloud:%s", cacheKey);

    // 2. 查 Caffeine 本地缓存（JVM 内存，微秒级）
    String cached = LOCAL_CACHE.getIfPresent(cacheKey);
    if (cached != null) return parseAndReturn(cached);

    // 3. 查 Redis 分布式缓存（网络 IO，毫秒级，try-catch 降级）
    try {
        cached = stringRedisTemplate.opsForValue().get(redisKey);
        if (cached != null) { LOCAL_CACHE.put(cacheKey, cached); return parseAndReturn(cached); }
    } catch (Exception e) { log.warn("Redis 查询失败，降级查询数据库"); }

    // 4. 查 MySQL 数据库
    Page<PictureVO> result = pictureService.getPictureVOPage(picturePage, request);

    // 5. 回写两级缓存（Redis 写入失败不影响响应）
    try {
        stringRedisTemplate.opsForValue().set(redisKey, json, 300+random, SECONDS);
        LOCAL_CACHE.put(cacheKey, json);
    } catch (Exception e) { LOCAL_CACHE.put(cacheKey, json); }
    return ResultUtils.success(result);
}
```

**缓存失效机制**：每次图片变更（上传/编辑/删除/审核/批量抓取）时调用 `clearListCache()`，递增 `cacheVersion` 并清空本地缓存。Redis 中的旧版本 key 不会被主动删除——依赖 TTL 自然过期（5~10 分钟随机），避免缓存雪崩。

**Redis 不可用时的降级策略**：try-catch 包裹所有 Redis 操作，失败时直接查数据库并仅写入本地 Caffeine 缓存。系统在 Redis 宕机时自动降级为"本地缓存 + 数据库"两级模式。

### 10.2 图片下载 — `/download/{id}`

```java
@GetMapping("/download/{id}")
public void downloadPicture(@PathVariable long id, HttpServletRequest request,
                            HttpServletResponse response) throws IOException {
    // 1. 权限校验：仅本人或管理员
    if (!picture.getUserId().equals(loginUser.getId()) && !userService.isAdmin(loginUser)) {
        throw new BusinessException(ErrorCode.NO_AUTH_ERROR);
    }

    // 2. 优先用 originalUrl（原始格式），其次用 url（webp）
    String downloadUrl = picture.getOriginalUrl() != null
            ? picture.getOriginalUrl() : picture.getUrl();

    // 3. 从 COS 读取文件流
    COSObject cosObject = cosManager.getObject(key);
    byte[] bytes = IOUtils.toByteArray(cosObject.getObjectContent());

    // 4. 设置下载响应头（RFC 5987 中文文件名编码）
    String filename = name + "." + ext;
    String asciiFallback = "download." + ext;
    String encoded = URLEncoder.encode(filename, UTF_8).replace("+", "%20");
    response.setHeader("Content-Disposition",
        "attachment; filename=\"" + asciiFallback + "\"; filename*=UTF-8''" + encoded);
    response.getOutputStream().write(bytes);
}
```

**设计要点**：
- **后端代理下载**：绕过 COS 跨域限制（COS 域名与前端不同源，fetch 会被 CORS 拦截）
- **双重文件名编码**：`filename="download.ext"`（ASCII 兜底）+ `filename*=UTF-8''中文名.ext`（现代浏览器支持）
- **格式回退**：`picFormat` 为空时默认 `"png"`，原始文件名纯数字时使用 `"图片_" + id`
