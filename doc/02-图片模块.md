# 图片模块

## 一、模块概述

图片模块是系统的核心业务模块，负责图片的**上传（COS + 入库）、多条件查询筛选、信息编辑、删除**。图片文件存储在腾讯云 COS，元数据存储在 MySQL 中，通过 `PictureVO` 视图对象关联上传者信息。

### 核心设计决策

1. **存储分离**：图片文件 → COS（高可用、CDN 加速），元数据 → MySQL（支持复杂查询和排序）
2. **JSON 标签**：`tags` 字段在数据库中存储为 JSON 数组字符串（`["风景","建筑"]`），VO 中转为 `List<String>`——兼顾数据库简单性和前端易用性
3. **双接口模式**：管理员接口返回原始 `Picture` 实体，公开接口返回 `PictureVO`（含关联 `UserVO`）
4. **更新机制**：上传接口传入 `id` 即为更新已有图片元数据（覆盖上传），不传则为新增

## 三、数据库表 — `picture`

```sql
CREATE TABLE picture (
    id           BIGINT PRIMARY KEY,         -- 雪花 ID
    url          VARCHAR(1024),              -- COS 图片完整 URL
    name         VARCHAR(256),               -- 图片名称
    introduction VARCHAR(800),               -- 图文简介（≤800 字）
    category     VARCHAR(64),                -- 分类（如：风景、人物、建筑）
    tags         VARCHAR(1024),              -- ★ JSON 数组字符串：["标签1","标签2"]
    picSize      BIGINT,                     -- 文件大小（字节）
    picWidth     INT,                        -- 图片宽度（像素）
    picHeight    INT,                        -- 图片高度（像素）
    picScale     DOUBLE,                     -- 宽高比（精确到小数点后 2 位）
    picFormat    VARCHAR(32),                -- 格式：jpg / png / webp
    userId       BIGINT,                     -- 上传者用户 ID
    createTime   DATETIME,
    editTime     DATETIME,                    -- 用户编辑时间
    updateTime   DATETIME,                    -- 系统更新时间
    isDelete     TINYINT DEFAULT 0           -- 逻辑删除
);
```

### 4.1 PictureVO 结构

@Data
public class PictureVO implements Serializable {

对比 `Picture` 实体：

| 差异 | Picture | PictureVO |
|------|---------|-----------|
| `tags` | `String`（`"[\"标签1\",\"标签2\"]"`） | `List<String>`（`["标签1", "标签2"]`） |
| `user` | 无 | `UserVO`（关联查询填充） |
| `isDelete` | 有（`@TableLogic`） | 无（对前端隐藏） |

### 4.2 实体 ↔ VO 转换方法

```java
// ★ Picture → PictureVO：tags 从 JSON 字符串反序列化为 List
public static PictureVO objToVo(Picture picture) {
    if (picture == null) return null;
    PictureVO pictureVO = new PictureVO();
    BeanUtils.copyProperties(picture, pictureVO);
    pictureVO.setTags(JSONUtil.toList(picture.getTags(), String.class));
    return pictureVO;
}

// ★ PictureVO → Picture：tags 从 List 序列化为 JSON 字符串
public static Picture voToObj(PictureVO pictureVO) {
    if (pictureVO == null) return null;
    Picture picture = new Picture();
    BeanUtils.copyProperties(pictureVO, picture);
    picture.setTags(JSONUtil.toJsonStr(pictureVO.getTags()));
    return picture;
}
```

`JSONUtil.toList()` 和 `JSONUtil.toJsonStr()` 来自 Hutool，分别负责 JSON 数组字符串的反序列化和序列化。例如：

```
数据库存储：   "[\"风景\",\"城市\",\"夜景\"]"
VO 中的 List：  ["风景", "城市", "夜景"]
```

## 五、图片上传流程 — `PictureServiceImpl.uploadPicture()`

```java
@Override
public PictureVO uploadPicture(MultipartFile multipartFile,
                                PictureUploadRequest pictureUploadRequest,
                                UserVO loginUser) {
```

### Step 1 — 判断新增还是更新

```java
    Long pictureId = null;
    if (pictureUploadRequest != null) {
        pictureId = pictureUploadRequest.getId();
    }

    // 如果传了 id，校验图片是否存在
    if (pictureId != null) {
        boolean exists = this.lambdaQuery()
                .eq(Picture::getId, pictureId)
                .exists();                          // exists() 比 count() > 0 更高效
        ThrowUtils.throwIf(!exists, ErrorCode.NOT_FOUND_ERROR, "图片不存在");
    }
```

设计思路：当用户需要"重新上传"替换已有图片时，在 `PictureUploadRequest` 中传入 `id`，系统会更新该图片记录的 COS URL 和元数据，而不是创建新记录。

### Step 2 — 调用 FileManager 上传到 COS

```java
    // 按用户 ID 划分上传目录
    String uploadPathPrefix = String.format("public/%s", loginUser.getId());
    UploadPictureResult uploadPictureResult = fileManager.uploadPicture(multipartFile, uploadPathPrefix);
```

COS 文件路径示例：`public/1823456789012345678/20260613_a3f8b2c1d4e5f6a7.jpg`

### Step 3 — 构造 Picture 实体入库

```java
    Picture picture = new Picture();
    picture.setUrl(uploadPictureResult.getUrl());
    picture.setName(uploadPictureResult.getPicName());
    picture.setPicSize(uploadPictureResult.getPicSize());
    picture.setPicWidth(uploadPictureResult.getPicWidth());
    picture.setPicHeight(uploadPictureResult.getPicHeight());
    picture.setPicScale(uploadPictureResult.getPicScale());
    picture.setPicFormat(uploadPictureResult.getPicFormat());
    picture.setUserId(loginUser.getId());

    if (pictureId != null) {
        picture.setId(pictureId);           // 更新模式：设置原 ID
        picture.setEditTime(new Date());
    }

    boolean result = this.saveOrUpdate(picture);  // saveOrUpdate：id 有值则更新，无值则插入
    ThrowUtils.throwIf(!result, ErrorCode.OPERATION_ERROR, "图片上传失败");
    return PictureVO.objToVo(picture);            // 实体 → VO 后返回
}
```

## 六、查询筛选 — `getQueryWrapper()` 深度解析

这是系统的核心查询方法，将前端的各种筛选条件转换为数据库 SQL 的 WHERE 子句。

```java
@Override
public QueryWrapper<Picture> getQueryWrapper(PictureQueryRequest pictureQueryRequest) {
    QueryWrapper<Picture> queryWrapper = new QueryWrapper<>();
    if (pictureQueryRequest == null) return queryWrapper;

    // ===== 跨字段模糊搜索 =====
    String searchText = pictureQueryRequest.getSearchText();
    if (StrUtil.isNotBlank(searchText)) {
        queryWrapper.and(qw -> qw
            .like("name", searchText)          // 名称包含关键词
            .or()
            .like("introduction", searchText)  // 或 简介包含关键词
        );
    }
```

`and()` 方法创建嵌套条件，相当于 `AND (name LIKE '%keyword%' OR introduction LIKE '%keyword%')`，确保搜索词同时匹配名称和简介。

```java
    // ===== 精确匹配 =====
    queryWrapper.eq(ObjUtil.isNotEmpty(id), "id", id);
    queryWrapper.eq(ObjUtil.isNotEmpty(userId), "userId", userId);
    queryWrapper.eq(ObjUtil.isNotEmpty(picWidth), "picWidth", picWidth);
    queryWrapper.eq(ObjUtil.isNotEmpty(picHeight), "picHeight", picHeight);
    queryWrapper.eq(ObjUtil.isNotEmpty(picSize), "picSize", picSize);
    queryWrapper.eq(ObjUtil.isNotEmpty(picScale), "picScale", picScale);
    queryWrapper.eq(StrUtil.isNotBlank(category), "category", category);
```

`eq(condition, column, value)` 中的 condition 是短路开关：当用户没有传入该字段时（值为 null 或空），此条件被自动跳过，SQL 中不会出现该筛选。

```java
    // ===== 模糊匹配 =====
    queryWrapper.like(StrUtil.isNotBlank(name), "name", name);
    queryWrapper.like(StrUtil.isNotBlank(introduction), "introduction", introduction);
    queryWrapper.like(StrUtil.isNotBlank(picFormat), "picFormat", picFormat);
```

```java
    // ===== JSON 数组标签查询 =====
    if (CollUtil.isNotEmpty(tags)) {
        for (String tag : tags) {
            queryWrapper.like("tags", "\"" + tag + "\"");
        }
    }
```

`tags` 在数据库中存储为 `["风景","城市","夜景"]`，查询时用 `LIKE '%"风景"%'` 匹配 JSON 数组中的元素。注意用 `\"` 包裹标签名避免误匹配（如搜索"风"不会匹配到"风景"）。

```java
    // ===== 排序 =====
    queryWrapper.orderBy(
        StrUtil.isNotEmpty(sortField),
        sortOrder.equals("ascend"),    // ascend → ASC，descend → DESC
        sortField
    );
    return queryWrapper;
}
```

## 七、图片 VO 分页查询 — `getPictureVOPage()`

```java
@Override
public Page<PictureVO> getPictureVOPage(Page<Picture> picturePage, HttpServletRequest request) {
    List<Picture> pictureList = picturePage.getRecords();
    Page<PictureVO> pictureVOPage = new Page<>(picturePage.getCurrent(),
                                                picturePage.getSize(),
                                                picturePage.getTotal());
    if (CollUtil.isEmpty(pictureList)) return pictureVOPage;

    // 1. Entity → VO 转换
    List<PictureVO> pictureVOList = pictureList.stream()
            .map(PictureVO::objToVo)
            .collect(Collectors.toList());

    // 2. ★ 批量关联查询用户信息（避免 N+1 查询）
    Set<Long> userIdSet = pictureList.stream()
            .map(Picture::getUserId)
            .collect(Collectors.toSet());
    Map<Long, List<User>> userIdUserListMap = userService.listByIds(userIdSet)
            .stream()
            .collect(Collectors.groupingBy(User::getId));

    // 3. 填充每个 PictureVO 的 user 字段
    pictureVOList.forEach(pictureVO -> {
        Long userId = pictureVO.getUserId();
        User user = null;
        if (userIdUserListMap.containsKey(userId)) {
            user = userIdUserListMap.get(userId).get(0);
        }
        pictureVO.setUser(userService.getUserVO(user));   // User → UserVO
    });

    pictureVOPage.setRecords(pictureVOList);
    return pictureVOPage;
}
```

**性能要点**：先收集所有 `userId` → 一次性 `listByIds()` 批量查询 → 按 userId 分组为 Map → 循环中直接取用。避免了在 for 循环中逐条查询用户信息（N+1 问题）。

## 八、数据校验 — `validPicture()`

```java
@Override
public void validPicture(Picture picture) {
    ThrowUtils.throwIf(picture == null, ErrorCode.PARAMS_ERROR);

    Long id = picture.getId();
    String url = picture.getUrl();
    String introduction = picture.getIntroduction();

    ThrowUtils.throwIf(ObjUtil.isNull(id), ErrorCode.PARAMS_ERROR, "id 不能为空");

    if (StrUtil.isNotBlank(url)) {
        ThrowUtils.throwIf(url.length() > 1024, ErrorCode.PARAMS_ERROR, "url 过长");
    }
    if (StrUtil.isNotBlank(introduction)) {
        ThrowUtils.throwIf(introduction.length() > 800, ErrorCode.PARAMS_ERROR, "简介过长");
    }
}
```

校验规则：`id` 必填（更新操作时），`url` ≤ 1024 字符，`introduction` ≤ 800 字符。

### 8 号接口 — `/edit` 编辑图片的完整流程

```java
@PostMapping("/edit")
public BaseResponse<Boolean> editPicture(@RequestBody PictureEditRequest pictureEditRequest,
                                          HttpServletRequest request) {
    // 1. 参数校验
    if (pictureEditRequest == null || pictureEditRequest.getId() <= 0) {
        throw new BusinessException(ErrorCode.PARAMS_ERROR);
    }

    // 2. DTO → Entity 转换，tags List → JSON String
    Picture picture = new Picture();
    BeanUtils.copyProperties(pictureEditRequest, picture);
    picture.setTags(JSONUtil.toJsonStr(pictureEditRequest.getTags()));
    picture.setEditTime(new Date());

    // 3. 数据校验
    pictureService.validPicture(picture);

    // 4. 权限校验：本人或管理员
    UserVO loginUser = userService.getLoginUser(request);
    Picture oldPicture = pictureService.getById(pictureEditRequest.getId());
    ThrowUtils.throwIf(oldPicture == null, ErrorCode.NOT_FOUND_ERROR);
    if (!oldPicture.getUserId().equals(loginUser.getId()) && !userService.isAdmin(loginUser)) {
        throw new BusinessException(ErrorCode.NO_AUTH_ERROR);
    }

    // 5. 执行更新
    boolean result = pictureService.updateById(picture);
    ThrowUtils.throwIf(!result, ErrorCode.OPERATION_ERROR);
    return ResultUtils.success(true);
}
```
